zhycms 使用手册 v2.1.0

基于 Flask 的轻量级企业网站 CMS — 目录结构 · 安装初始化 · 部署 · 权限与安全 · 备份运维 · 消息通知 · SEO 性能 · 模板制作教程 · v1.1→v2.0 升级迁移

项目简介

zhycms 是一个基于 Flask + SQLAlchemy 的轻量级内容管理系统，内置多主题模板引擎、栏目级模板选择、自定义字段、表单收集、SEO 优化等能力，适合搭建企业官网、资讯门户、产品展示站等。

v2.0 围绕「企业级安全、可控、可运维」新增八大模块：RBAC 权限体系、审计日志、内容工作流、备份恢复、登录安全加固、上传安全与图片优化、表单消息通知、SEO 与站点性能。

从 v1.1 升级：v2.0 新增 9 张数据表、旧表补 12 列与 4 个依赖，请先阅读项目根目录的 UPGRADE.md 升级迁移指南，并执行幂等迁移脚本 scripts/upgrade_v2.py 完成数据库迁移（仅启动程序无法完成迁移，且可能把原本隐藏的文章错误公开）。

特性一览

  • 多主题模板系统：前台模板按主题组织，后台一键切换。内置 default、blue 两套通用聚合主题，以及 manufacturing（制造业）、service（服务业）两套行业专用主题。
  • 演示数据一键生成：初始化时可选「制造业」或「服务业」示例，自动生成栏目、文章、碎片、友情链接与演示图片并切换主题。
  • CMS 标识与企业标识分离：后台 CMS 名称/版权固定不可改，前台网站名称/版权可独立配置。
  • 栏目级模板选择：每个栏目可指定独立的列表页/内容页/单页模板，未指定自动回退默认。
  • 自定义字段：栏目和文章支持自定义字段（文本/富文本/图片/文件/URL/数字等）。
  • 表单收集：可视化表单设计，支持文本/手机/邮箱/单选/多选/文件上传，带图形验证码防刷，提交数据可导出；v2.0 支持提交后邮件/企业微信实时通知。
  • SEO 优化 / 碎片管理 / 友情链接 / 图片上传 / 验证码登录 / 首次初始化引导。
  • v2.0 企业级能力：RBAC 角色权限、审计日志、内容工作流与版本还原、数据库备份恢复、登录防暴破、上传内容安全校验、伪静态与页面缓存。

二、安装与初始化

环境要求

  • Python 3.9+
  • SQLite（默认，开箱即用）或 MySQL / PostgreSQL

安装步骤

# 克隆代码
git clone <your-repo-url> zhycms
cd zhycms

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

# 安装依赖（国内建议使用镜像源加速）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
# 清华源： -i https://pypi.tuna.tsinghua.edu.cn/simple

# 启动开发服务器
python run.py
requirements.txt 已内置 MySQL 驱动 PyMySQL 与 PostgreSQL 驱动 psycopg2-binary，初始化时选择对应数据库类型即可，无需额外安装。

初始化向导

浏览器访问 http://127.0.0.1:5000，首次访问会自动跳转到 /admin/setup 初始化向导。向导中需要填写：

  • 管理员账号（至少 3 个字符）与密码（至少 6 个字符，需二次确认）
  • 数据库类型：SQLite / MySQL / PostgreSQL（见下）
  • 演示数据：不生成 / 制造业 / 服务业

提交后系统会创建管理员、写入默认设置，并按选择生成演示数据，随后跳转登录页。

数据库选择

类型说明需要填写
SQLite默认，直接生成 instance/zhycms.db 文件，零配置无
MySQL连接已有 MySQL 服务，默认端口 3306主机、端口、数据库名、用户名、密码
PostgreSQL连接已有 PostgreSQL 服务，默认端口 5432主机、端口、数据库名、用户名、密码
选择 MySQL/PostgreSQL 时，向导会先测试连接，成功后才将连接信息写入 instance/db_config.json 并热切换数据库引擎；若切换失败会自动回滚到原库，保证应用可继续运行。
数据库 URI 解析优先级（见 app/config.py）：
环境变量 ZHOCMS_DB_URI > instance/db_config.json（初始化向导所存） > 默认 SQLite。

三、部署

开发模式

python run.py
# 监听 0.0.0.0:5000，默认开启 DEBUG，代码/模板改动自动重载

生产部署

# 直接运行（关闭 DEBUG）
ZHOCMS_ENV=production ZHOCMS_SECRET_KEY=your-secret python run.py

# 或使用 gunicorn（推荐）
gunicorn -w 4 -b 0.0.0.0:5000 "run:app"
生产环境注意：务必通过 ZHOCMS_SECRET_KEY 设置自定义会话密钥；建议在 gunicorn 前置 Nginx 反向代理并托管 app/static/ 静态资源。

环境变量

变量默认值说明
ZHOCMS_ENVdevelopment配置模式：development / production
ZHOCMS_SECRET_KEY内置默认值会话加密密钥，生产环境必须修改
ZHOCMS_DB_URIsqlite:///instance/zhycms.db数据库 URI，可换成 MySQL/PostgreSQL；优先级最高

四、CMS 标识与网站标识

系统严格区分「CMS 自身标识」与「前台企业标识」四个概念，避免演示数据或用户配置误改后台品牌：

概念显示位置取值来源可否修改
CMS 名称后台顶栏 / 登录页 / 后台标题Setting.CMS_NAME 固定常量❌ 不可改
后台版权后台底部Setting.CMS_COPYRIGHT 固定常量❌ 不可改
网站名称前台导航 / 首页 / 页脚Setting 'site_name'（企业名）✅ 网站设置可改
前台版权前台底部Setting 'footer_copyright'✅ 网站设置可改
约定：后台模板一律使用 cms_name / cms_copyright（由 app/__init__.py 的上下文处理器注入），不得读取 site_settings.site_name / site_settings.footer_copyright（那是前台企业信息）；前台模板则相反。

五、演示数据与行业主题

选项生成内容自动切换主题
不生成仅创建管理员，空站点保持 default
制造业精密机械制造企业示例：关于我们、产品中心、新闻中心、联系我们等栏目 + 文章 + 碎片 + 友情链接 + 演示图片manufacturing（产品置顶）
服务业企业管理咨询公司示例：关于我们、服务项目、行业动态、客户案例、联系我们等栏目 + 文章 + 碎片 + 友情链接 + 演示图片service（公司介绍置顶）
  • 演示数据由 app/utils/bootstrap.py 的 generate_demo_data(industry) 生成。
  • 每次生成会先调用 _clean_demo_data() 按外键依赖顺序清理旧数据（表单 → 文章 → 栏目 → 碎片 → 友情链接），因此可在两个行业间反复切换而不会触发 slug 唯一约束冲突。
  • 演示图片位于 app/static/uploads/demo/（制造业 mfg_*、服务业 svc_*），无需联网即可展示。
  • 演示数据只写入前台企业信息，不会改动后台 CMS 名称与版权。

六、模板制作教程

zhycms 前台采用 多主题 + 栏目级模板 的双层机制，主题可在网站设置一键切换，栏目可单独指定列表/内容/单页模板。模板基于 Jinja2 + Bootstrap 4。

1. 主题目录结构

所有主题存放在 app/frontend/templates/themes/ 下，每个主题是一个独立目录，目录名即主题名：

themes/default/
├── base.html            # 基础布局（必须）
├── index.html           # 首页（必须）
├── list.html            # 列表页默认模板（必须）
├── article.html         # 文章详情默认模板（必须）
├── page.html            # 单页默认模板（必须）
├── list_card.html       # 卡片式列表（可选，栏目备选模板）
├── column_children.html # 父栏目展示子栏目列表
├── search.html          # 搜索结果页
├── form.html            # 表单提交页（含验证码）
├── form_closed.html     # 表单关闭提示页
├── closed.html          # 站点关闭提示页
├── 404.html
└── 500.html

必备模板

文件用途
base.html全站基础骨架，所有页面通过 {% extends theme_base %} 继承
index.html站点首页
list.html列表栏目默认列表页（名称固定 list）
article.html文章详情默认页（名称固定 article）
page.html单页栏目默认页（名称固定 page）
404.html / 500.html错误页
closed.html站点关闭时展示

可选模板（栏目级备选）

凡以 list、article、page 开头的 .html 文件，会自动出现在后台栏目编辑页的下拉选项中：

  • list_xxx.html → 列表栏目可选用
  • article_xxx.html → 文章详情页可选用
  • page_xxx.html → 单页栏目可选用
受保护模板（即使以上述前缀开头也不会列为栏目备选，因为它们是系统级模板）：
base、404、500、closed、form_closed、index、search、column_children、form

2. 创建一个新主题

以创建名为 green 的绿色风格主题为例：

步骤 1：复制默认主题作为起点

cp -r app/frontend/templates/themes/default app/frontend/templates/themes/green

步骤 2：修改 base.html 中的样式

/* 主题色：绿色 */
.navbar { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%) !important; }
.footer { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%); color:#e8f5e9; }
.card-header { background:#2e7d32; color:#fff; }
.btn-primary { background-color:#2e7d32; border-color:#2e7d32; }
a { color:#2e7d32; } a:hover { color:#1b5e20; }

步骤 3：在后台启用

进入 后台 → 网站设置 → 前台主题，下拉框会自动出现 green 选项，选中保存即可。

主题的发现是自动的：扫描 themes/ 下所有子目录，无需在代码中注册。

3. 模板继承与 theme_base

所有页面模板通过 {% extends theme_base %} 继承当前主题的 base.html，而不是写死路径：

{% extends theme_base %}
{% block title %}页面标题{% endblock %}
{% block content %}
  页面内容
{% endblock %}

theme_base 由上下文处理器注入，值类似 themes/default/base.html，切换主题时自动找到对应的 base.html。

base.html 必须提供的 block

Block 名用途
title<title> 标签内容
css页面级 CSS（在 <head> 内）
content主体内容
js页面级 JS（在 </body> 前）

4. 全局模板变量

以下变量在所有前台模板中可直接使用（由 app/__init__.py 的 context_processor 注入）：

变量类型说明
site_settingsdict站点设置，含前台企业标识：site_name、site_subtitle、site_logo、footer_copyright 等
site_fragmentsdict碎片内容，键为碎片 slug，值为 Fragment 对象（访问 .value）
nav_columnslist顶层栏目列表
current_themestr当前主题名（如 default）
theme_basestr当前主题 base 模板路径
cms_name / cms_copyrightstrCMS 名称 / 后台版权（固定），仅后台使用

视图函数传入的常用变量

  • 首页 index.html：nav、first_page、latest_articles、friend_links、seo；行业主题另有 about_col、products_col/products、services_col/services、news_col/news、cases_col/cases（按 slug 约定收集，通用主题忽略）
  • 列表页 list.html：column、articles、pagination、nav、seo
  • 文章详情 article.html：column、article、fields、latest_articles、prev_article、next_article、nav、seo
  • 单页 page.html：column、nav、seo
  • 表单 form.html：form、fields、nav、seo
  • 搜索 search.html：keyword、results、nav、seo
  • 父栏目 column_children.html：column、children、nav、seo

6. URL 生成与自定义过滤器

{{ url_for('frontend.index') }}                                   {# 首页 #}
{{ url_for('frontend.column_detail', slug=column.slug) }}         {# 栏目页 #}
{{ url_for('frontend.column_detail', slug=column.slug, page=2) }} {# 带分页 #}
{{ url_for('frontend.article_detail', slug=column.slug, aid=article.id) }} {# 文章 #}
{{ url_for('frontend.form_submit', slug=form.slug) }}             {# 表单 #}
{{ url_for('frontend.search') }}                                  {# 搜索 #}

伪静态分页助手（v2.0）

v2.0 起全局注入 frontend_pager_url(column, page)：SEO 高级中开启伪静态时自动输出 /{slug}-{N}.html（第 1 页为 /{slug}.html），关闭时输出 /column/{slug}?page=N。自定义列表模板的分页链接请统一使用该助手，不要写死动态 URL：

<a href="{{ frontend_pager_url(column, pagination.prev_num or 1) }}">&laquo; 上一页</a>
{% for p in pagination.iter_pages() %}
  <a href="{{ frontend_pager_url(column, p) }}">{{ p }}</a>
{% endfor %}
<a href="{{ frontend_pager_url(column, pagination.next_num or pagination.page) }}">下一页 &raquo;</a>
文章详情页可直接使用 url_for('frontend.article_detail', ...)，系统会自动识别；伪静态开启时也可直接输出 /{{ article.id }}.html。
过滤器用途示例
date格式化日期{{ article.published_at|date }} → 2026-08-06
datetime格式化日期时间{{ article.published_at|datetime }} → 2026-08-06 22:30
truncate_text截断文本{{ article.summary|truncate_text(80) }}

7. 制作栏目级备选模板

以制作「卡片式列表模板」为例。步骤 1：在主题目录下创建以 list 开头的文件 list_card.html。步骤 2：编写模板内容（继承 theme_base，遍历 articles 渲染卡片，用 pagination 生成分页）。步骤 3：进入后台栏目编辑页，「列表页模板」下拉框会出现 list_card 选项，选中保存即可。

前缀对应栏目模板类型出现位置
list_*列表页模板列表栏目的「列表页模板」下拉
article_*内容页模板列表栏目的「内容页模板」下拉
page_*单页模板单页栏目的「单页模板」下拉
若栏目指定的模板在当前主题中不存在（如切换主题后新主题没有该模板），系统会自动回退到默认模板（list / article / page），不会报错。

自定义字段渲染示例（文章详情页片段）

{% for f in fields %}
  {% set val = article.get_field_value(f.id) %}
  {% if val %}
  <tr><th>{{ f.label }}</th><td>
    {% if f.field_type == 'image' %}<img src="{{ val }}">
    {% elif f.field_type == 'file' %}<a href="{{ val }}">下载</a>
    {% elif f.field_type == 'url' %}<a href="{{ val }}" target="_blank">{{ val }}</a>
    {% elif f.field_type == 'richtext' %}{{ val|safe }}
    {% else %}{{ val }}{% endif %}
  </td></tr>
  {% endif %}
{% endfor %}

8. 模板制作检查清单

  • 目录 app/frontend/templates/themes/<主题名>/ 已创建
  • 包含必备文件：base / index / list / article / page / 404 / 500 / closed
  • 所有页面通过 {% extends theme_base %} 继承（不硬编码主题路径）
  • base.html 提供 title / css / content / js 四个 block
  • 富文本内容使用 |safe 过滤器
  • 列表页、文章页的分页链接正确使用 pagination 对象；分页链接统一使用 frontend_pager_url(column, page) 助手以兼容伪静态开关
  • 后台「网站设置 → 前台主题」下拉框能看到新主题
  • 切换到新主题后，首页、栏目页、文章页、单页、404 均能正常访问
  • 自定义字段按 field_type 区分图片/文件/URL/富文本正确渲染

9. 调试技巧

  • 调试模式：python run.py 默认开启 DEBUG，模板修改自动重载。
  • 查看当前主题：在任意模板中输出 {{ current_theme }}。
  • 查看可用模板：Python Shell 中执行 list_themes() / list_theme_templates(category='list')（见 app/utils/themes.py）。
  • 模板找不到报错：检查文件名是否准确（区分大小写），是否放在正确的主题目录下。

七、用户、角色与权限（RBAC）

后台菜单 用户权限 → 用户列表 / 角色与权限（v2.0 新增）。

权限模型

  • 权限点两级授权：角色可勾选一组权限点，同时控制后台菜单可见性与操作按钮/接口（如文章发布、备份恢复、配置修改、用户管理）。
  • 多角色并集：一个用户可绑定多个角色，最终权限为所有角色权限点的并集。
  • 内容粒度授权：支持按栏目授予文章管理权限（如「只管理新闻中心」），实现内容运营岗位的最小权限分配。
  • 超级管理员：内置超管不受任何权限限制，普通用户未授权的菜单不可见、直接访问接口返回 403 并记录审计日志。
角色删除前会先解除用户绑定；用户被禁用后立即无法登录，已有会话在下一次请求时失效。

八、内容工作流与版本管理

文章编辑流程从 v1.1 的「直接发布」升级为可审核的工作流（v2.0 新增）：

状态流转

草稿(draft) ──提交审核──> 待审核(pending) ──审核通过──> 已发布(published)
    ▲                          │
    └────────驳回──────────────┘ 已驳回(rejected，需填写驳回原因)
  • 无发布权限的作者只能保存草稿并提交审核；有发布权限的编辑可直接发布。
  • 待审核文章只有具备审核权限的用户可见可操作，前台不展示。
  • 驳回时必须填写原因，作者可在文章列表看到驳回原因并修改后重新提交。

版本快照

  • 文章每次保存自动生成版本快照，记录标题/正文/摘要等完整内容与操作时间。
  • 文章编辑页 版本历史 中可查看任意两个版本的差异，支持一键还原到指定版本（还原动作本身也会生成新版本，可安全撤销）。

九、备份与恢复

后台菜单 备份运维 → 备份列表（v2.0 新增），备份文件存放于 instance/backups/。

备份方式

方式适用说明
MySQL 逻辑备份MySQL / MariaDB调用 mysqldump 导出全库结构与数据，gzip 压缩为 .sql.gz
PostgreSQL 备份PostgreSQL调用 pg_dump，同样 gzip 压缩
JSON 备份任意数据库与数据库类型无关的通用格式，适合小站点迁移或跨库切换

操作说明

  • 立即备份：选择备份方式一键执行，完成后列表显示文件名、大小、耗时与操作人。
  • 下载：将备份文件下载到本地异地保存。
  • 恢复：从备份文件一键恢复。恢复前系统自动提交并释放数据库连接池，避免 DROP TABLE 时被自身连接的元数据锁阻塞。
  • 删除：清理过期备份文件与记录。
恢复前务必确认：恢复操作会用备份内容覆盖当前数据库全部数据，且要求运行环境具备 mysqldump / pg_dump 命令（JSON 方式除外）。建议先下载一份当前备份再执行恢复。

十、表单消息通知

后台菜单 系统设置 → 消息通知（v2.0 新增）。配置后，前台表单每收到一条提交都会实时推送到指定渠道。

邮件通知

配置项说明
SMTP 服务器 / 端口 / SSL如 smtp.exmail.qq.com / 465 / 开启
SMTP 账号 / 密码登录邮箱与授权码
发件人显示名 / 发件地址如「官网线索通知」/ noreply@example.com
收件人列表逗号分隔多个，如销售、客服各一份

邮件正文为 HTML 表格，包含：表单名称、提交时间、访客 IP、来源页面与全部字段值。

企业微信通知

填写群机器人 Webhook 地址即可，支持配置 @ 的手机号列表（逗号分隔），消息为 markdown 格式，含与邮件一致的完整信息。

开关逻辑

  • 「邮件通知」「企业微信通知」两个渠道均有独立开关。
  • 「全局通知开关」总控：关闭时调用方静默跳过，不发送任何消息，也不影响表单正常提交入库。
  • 配置保存与每次通知触发均写入审计日志，便于追查「有没有发出去」。
建议：配置完成后，在前台提交一条测试表单验证两个渠道；企业微信 Webhook 可先用 curl 推一条测试消息确认机器人有效。

十一、SEO 与站点性能

后台菜单 系统设置 → SEO 高级（v2.0 新增）。

伪静态 URL

开启伪静态后，前台自动支持以下 URL（关闭后这些地址返回 404，动态 URL 照常可用）：

URL含义等价动态 URL
/about.html栏目页（第一页）/column/about
/about-2.html栏目列表页第 2 页/column/about?page=2
/article-12.html文章详情/column/{slug}/article/12
  • 页面中的栏目、文章、分页链接会同步输出为伪静态格式（第 1 页输出 /about.html，不带 -1 后缀；第 N 页输出 /about-N.html）。
  • 访问 /about-1.html 会 301/302 规范化到 /about.html，避免搜索引擎收录重复页面。
  • 含连字符数字的栏目 slug（如 news-2024）可正确解析，不会被误切分为栏目 + 页码。
  • 开关即时生效，无需重启；自定义模板请使用全局助手 frontend_pager_url(column, page) 生成分页链接（见模板教程第 6 节）。

sitemap 与 robots

  • sitemap.xml：自动收录全部栏目与文章，栏目页/文章页的更新频率（changefreq）与优先级（priority）独立配置；伪静态开启时输出 .html 地址。
  • robots.txt：内置默认规则（跟随后台前缀 Disallow、屏蔽 /form/ 表单地址、声明 Sitemap），支持追加自定义规则；后台前缀变更后默认规则自动跟随。

页面缓存与图片 ALT

  • 页面缓存：基于 Flask-Caching，首页 / 栏目列表页 / 文章详情页可分别设置 TTL（默认 3600 / 1800 / 7200 秒）；发布、编辑、删除内容后自动清理对应缓存，不会出现「改了前台不更新」。
  • 图片默认 ALT：设置默认值后，前台渲染时自动为缺失或空 alt 的 <img> 填充（已设置 alt 的保留原值），提升无障碍访问与图片 SEO。
  • 图片ALT批量管理（系统设置 → 图片ALT批量管理）：后台工具页，批量排查全站文章/单页正文中的图片 ALT 缺失情况。

十二、安全加固

登录防暴破（v2.0）

  • 连续输错密码达到阈值（默认 5 次）自动锁定账号，锁定期内即使密码正确也会被拒绝；锁定时长默认 10 分钟，到期自动解锁。次数与时长均可在 系统设置 → 后台安全 中调整。
  • 登录页配备图形验证码；验证码错误会记录失败日志但不累计密码失败次数（验证码先于密码验证）。
  • 异地登录提醒：检测到与上次登录不同的 IP 城市时，登录成功后顶部展示一次性安全提醒横幅（可在设置中关闭）。
  • 所有登录行为（成功/失败/锁定）均写入 登录日志（系统设置 → 登录日志）。

后台路由前缀即时生效（v2.0）

系统设置 → 后台安全 中修改后台前缀（如 admin → manage-x8y2）后，v2.0 起即时生效、无需重启服务：新前缀立即可访问，旧前缀立即失效（404），后台页内跳转自动使用新前缀。历史前缀保存在 instance/admin_config.json，忘记路由时删除该文件可恢复默认 admin。

上传安全与图片优化（v2.0）

后台菜单 系统设置 → 上传安全，以下能力默认开启：

  • 后缀 + MIME 双重校验：除了校验后缀白名单，还检查文件真实内容（magic bytes）；伪装成 .jpg 的 PHP/Shell/可执行文件（含 <?php、#!、MZ、ELF 等特征）直接拒绝；图片后缀强制要求内容为真实图片。
  • SHA-256 内容去重：相同内容的文件全局只保存一份，多处引用自动计数（删除引用计数归零才真正清理磁盘）。
  • 图片自动压缩 + 缩略图：JPG/PNG 上传后自动压缩（质量默认 80，可调）并生成 300px 宽缩略图（可调），显著降低磁盘与流量开销。
  • 单文件大小上限默认 10MB，可配置；超限直接拒绝并给出明确提示。
  • 所有上传文件建立统一索引（原始大小/压缩后大小/宽高/缩略图路径/引用计数），可在后台查看与管理。

审计日志（v2.0）

后台菜单 审计日志：登录/登出、配置变更、内容增删改与发布审核、备份恢复、用户与权限调整等关键操作全量留痕，记录操作人、IP、操作时间、操作类型与详情；支持按模块、操作类型、操作人与时间范围检索，为安全追溯提供依据。

十三、v1.1 → v2.0 升级迁移

正在运行 v1.1 及更早 1.x 版本的站点升级到 v2.0 前，请务必完整阅读项目根目录的 UPGRADE.md（升级迁移指南）。本章为速览。

升级前必读：四个关键变化

变化说明需要做的事
用户权限语义v1.1 所有用户默认超级管理员；v2.0 引入 RBAC，新建用户默认无权限升级后到「用户权限 → 用户列表」收紧非管理员的超管标志并分配角色
文章状态机is_enabled 开关升级为工作流状态（迁移自动回填，前台展示效果不变）无需手工处理；确认隐藏文章升级后仍不可见
登录安全默认启用失败 5 次锁定 10 分钟、图形验证码、异地提醒告知全体后台用户；弱密码账号建议一并改密
上传行为变化MIME 双重校验/SHA-256 去重/压缩缩略图默认开启，仅影响新上传伪装成图片的脚本将无法上传

升级步骤速览

# 0. 备份站点目录与数据库（必做！）

# 1. 停服并更新代码到 v2.0
git fetch && git checkout v2.0

# 2. 更新依赖（新增 4 个；Linux 需补系统库 libmagic）
pip install -r requirements.txt
sudo apt install -y libmagic1        # Debian/Ubuntu

# 3. 执行数据库迁移（幂等脚本，可重复运行）
.venv/bin/python scripts/upgrade_v2.py

# 4. 启动服务，按 UPGRADE.md 的验证清单逐项核对

为什么必须运行迁移脚本

v2.0 新增 9 张数据表、旧表补 12 列并回填文章状态。仅启动程序无法完成迁移：db.create_all() 只建新表、不会给旧表加列；若跳过数据回填，ALTER ADD COLUMN ... DEFAULT 'published' 会让原本隐藏的文章被错误公开。迁移脚本已通过版本记录保证幂等，可安全重复执行。

升级后验证要点

  • 原本隐藏的文章（is_enabled=0）升级后仍然不可见
  • 后台登录正常（需输入图形验证码）；连续错 5 次密码会锁定 10 分钟
  • 用户列表已审查 is_super 标志，普通用户已分配角色
  • 新建文章默认草稿，可提交审核/发布；版本历史可用
  • 上传 JPG 生成缩略图且压缩；伪静态、消息通知、备份按需配置验证

完整内容（手工 SQL、回滚方案、变更明细附录）见 UPGRADE.md。
