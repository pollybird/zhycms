项目简介

ZhyCMS 是一个基于 Flask + SQLAlchemy 的轻量级企业内容管理系统，采用「插件优先、主题驱动」架构，适合搭建企业官网、资讯门户、产品展示站等。

系统严格区分「CMS 自身标识」与「前台企业标识」，后台品牌固定不可改，前台信息独立配置。

从 v1.1 升级：v2.0 起新增 9 张数据表、旧表补 12 列，请先阅读项目根目录 UPGRADE.md 并执行 scripts/upgrade_v2.py 完成迁移。

安装与初始化

环境要求

  • Python 3.9+
  • 数据库：MySQL 5.7+ / PostgreSQL 12+（生产推荐）/ SQLite（仅开发）
生产环境请使用 MySQL 或 PostgreSQL。SQLite 不支持并发写入，容易锁表。

安装步骤

git clone https://gitee.com/pollybird/zhycms
cd zhycms
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python run.py

初始化向导

首次访问 http://127.0.0.1:5000 自动跳转 /admin/setup，需配置：

  • 管理员账号（≥3 字符）与密码（≥6 字符）
  • 数据库类型（MySQL / PostgreSQL / SQLite）
  • 演示数据：不生成 / 制造业 / 服务业 / Manufacturing (EN) / English Default

数据库选择

类型说明需填写
MySQL生产首选，默认端口 3306主机、端口、库名、用户名、密码
PostgreSQL生产可选，默认端口 5432主机、端口、库名、用户名、密码
SQLite零配置，仅开发/测试无
数据库 URI 优先级：环境变量 ZHYCMS_DB_URI > instance/db_config.json > 默认 SQLite。

部署方式

开发模式

python run.py
# 监听 0.0.0.0:5000，DEBUG 模式，代码/模板改动自动重载

生产部署

# 方式一
ZHYCMS_ENV=production ZHYCMS_SECRET_KEY=your-secret python run.py

# 方式二（推荐）
gunicorn -w 4 -b 0.0.0.0:5000 "run:app"
# 或
python -m gunicorn -w 4 -b 0.0.0.0:5000 wsgi:app
生产环境务必设置 ZHYCMS_SECRET_KEY；建议前置 Nginx 反向代理并托管静态资源。

Docker 部署 v2.4

一键安装（推荐，自动生成密钥与密码、配置镜像加速）：

bash docker/install.sh

或手动配置：

cp docker/.env.example .env
# 编辑 .env 修改密钥和数据库密码

# MySQL 方案
docker compose --profile mysql up -d

# PostgreSQL 方案
docker compose --profile postgres up -d

# 访问 http://localhost:5000 完成初始化

容器启动时自动执行：数据库迁移 → 恢复演示图片 → 编译 i18n → 启动 gunicorn。instance/ 和上传目录通过 volume 持久化。卸载运行 bash docker/uninstall.sh。

用户、角色与权限（RBAC）

后台菜单：用户权限 → 用户列表 / 角色与权限

  • 权限点两级授权：角色勾选权限点，同时控制后台菜单可见性与操作按钮/接口。
  • 多角色并集：一个用户可绑定多个角色，权限取并集。
  • 内容粒度授权：可按栏目授予文章管理权限（如「只管理新闻中心」）。
  • 超级管理员：内置超管不受权限限制；未授权菜单不可见，接口返回 403 并记录审计。
角色删除前自动解除用户绑定；用户禁用后立即无法登录，已有会话下次请求时失效。

内容工作流与版本管理

状态流转

草稿(draft) ──提交审核──→ 待审核(pending) ──审核通过──→ 已发布(published)
    ↑                          │
    └────────驳回──────────────┘ 已驳回(rejected)
  • 无发布权限的作者只能保存草稿并提交审核；有权限的编辑可直接发布。
  • 待审核文章仅具备审核权限的用户可见，前台不展示。
  • 驳回时必须填写原因，作者可修改后重新提交。

版本快照

文章每次保存自动生成版本快照，支持查看差异与一键还原（还原动作本身也生成新版本，可安全撤销）。

备份与恢复

后台菜单：备份运维 → 备份列表

方式适用说明
MySQL 逻辑备份MySQL / MariaDBmysqldump 导出，gzip 压缩
PostgreSQL 备份PostgreSQLpg_dump 导出，gzip 压缩

开关逻辑

  • 邮件、企微两个渠道均有独立开关。
  • 「全局通知开关」总控：关闭时静默跳过，不影响表单正常提交。
  • 配置保存与每次通知触发均写入审计日志。

SEO 与站点性能

后台菜单：系统设置 → SEO 高级

伪静态 URL

URL含义等价动态 URL
/about.html栏目页（第 1 页）/column/about
/about-2.html栏目列表页第 2 页/column/about?page=2
/article-12.html文章详情/column/{slug}/article/12
  • 开关即时生效，无需重启；关闭后伪静态地址返回 404。
  • 分页链接统一使用 frontend_pager_url(column, page) 助手，自动适配伪静态开关。
  • /about-1.html 自动 301 规范到 /about.html。

sitemap 与 robots

  • sitemap.xml：自动收录栏目与文章，独立配置更新频率/优先级；插件 URL 自动聚合。
  • robots.txt：内置默认规则，支持追加自定义；后台前缀变更后自动跟随。

页面缓存与图片 ALT

  • 页面缓存：基于 Flask-Caching，首页/栏目/文章独立 TTL（默认 3600/1800/7200 秒）；内容变更后自动清理对应缓存。
  • 图片默认 ALT：为缺失或空 alt 的 <img> 自动填充默认值。
  • 图片 ALT 批量管理：后台工具页，批量排查全站图片 ALT 缺失情况。

安全加固

登录防暴破

  • 连续输错密码 5 次（可配置）自动锁定 10 分钟（可配置），锁定期内正确密码也被拒绝。
  • 登录页图形验证码：错误不累计密码失败次数。
  • 异地 IP 登录提醒：检测到不同城市 IP 时顶部展示一次性安全横幅。
  • 所有登录行为写入登录日志。

后台路由前缀

系统设置 → 后台安全 中修改前缀（如 admin → manage-x8y2）后即时生效，无需重启。旧前缀立即 404，页内跳转自动使用新前缀。忘记路由可删除 instance/admin_config.json 恢复默认。

上传安全与图片优化

后台菜单：系统设置 → 上传安全，默认全部开启：

  • 后缀 + MIME 双重校验：检查文件真实内容（magic bytes），伪装成图片的脚本直接拒绝。
  • SHA-256 内容去重：相同内容只存一份，多处引用自动计数。
  • 图片自动压缩 + 缩略图：JPG/PNG 压缩（默认质量 80）并生成 300px 缩略图。
  • 单文件上限默认 10MB，可配置。

审计日志

后台菜单：审计日志。登录/登出、配置变更、内容增删改、备份恢复、权限调整等关键操作全量留痕，记录操作人、IP、时间、类型与详情；支持按模块、操作类型、操作人与时间范围检索。

模板制作教程

前台采用 多主题 + 栏目级模板 双层机制，基于 Jinja2 + Bootstrap 4。

主题目录结构

主题位于 app/frontend/templates/themes/<slug>/：

themes/default/
├── manifest.json          # 主题元数据
├── base.html              # 基础布局（必须）
├── index.html             # 首页（必须）
├── list.html              # 列表页默认（必须）
├── article.html           # 文章详情默认（必须）
├── page.html              # 单页默认（必须）
├── 404.html / 500.html    # 错误页（必须）
├── closed.html            # 站点关闭提示
├── list_card.html         # 栏目备选模板（可选）
├── search.html            # 搜索结果页
├── css/                   # 样式目录（v2.2 起外置）
│   └── style.css
├── js/                    # 脚本目录（可选）
├── images/                # 静态图片（可选）
└── fonts/                 # 字体文件（可选）

必备模板检查

v2.2 起上传/启用前强制检查 7 个必备模板（index/list/article/page/base/404/500.html），任一缺失拒绝启用。manifest 的 template_required 可追加额外必备声明。

静态资源引用

<link rel="stylesheet" href="{{ url_for('frontend.theme_asset', slug=current_theme, filename='css/style.css') }}">
资源路由仅放行 css/js/images/fonts 四个子目录并拦截路径穿越；全部资源随主题打包下载时一并带走。

创建新主题

  1. cp -r themes/default themes/green
  2. 修改 css/style.css 与 manifest.json（slug 需与目录名一致）
  3. 后台 系统设置 → 主题管理 → 启用
主题自动发现：扫描 themes/ 下所有子目录，无需代码注册。

模板继承

所有页面通过 {% extends theme_base %} 继承当前主题的 base.html：

{% extends theme_base %}
{% block title %}页面标题{% endblock %}
{% block content %}页面内容{% endblock %}

base.html 必须提供 title / css / content / js 四个 block。

全局模板变量

变量类型说明
site_settingsdict站点设置（site_name, site_logo, footer_copyright 等）
site_fragmentsdict碎片内容，键为 slug
nav_columnslist顶层栏目列表
current_themestr当前主题名
theme_basestr当前主题 base 模板路径

  <a href="{{ frontend_pager_url(column, p) }}">{{ p }}</a>
{% endfor %}

datetime{{ article.published_at|datetime }} → 2026-08-06 22:30
truncate_text{{ article.summary|truncate_text(80) }}

栏目级备选模板

创建 list_xxx.html / article_xxx.html / page_xxx.html，后台栏目编辑页自动出现在下拉选项中。受保护模板（不会列为备选）：base, 404, 500, closed, form_closed, index, search, column_children, form。

若栏目指定模板在当前主题中不存在，自动回退默认模板，不会报错。

模板制作检查清单

  • 包含必备文件：base / index / list / article / page / 404 / 500 / closed
  • 所有页面通过 {% extends theme_base %} 继承
  • 富文本内容使用 |safe 过滤器
  • 分页链接统一使用 frontend_pager_url()
  • 自定义字段按 field_type 区分渲染

主题管理 v2.2

入口：系统设置 → 主题管理（权限 system:settings）。

主题列表

  • 使用中（绿色高亮）：当前启用主题。
  • 未启用：可一键启用。
  • 模板不完整（标红）：缺失必备模板，操作按钮灰显。

上传主题

支持 .zip / .tar.gz / .tgz，8 步校验：

  1. 扩展名白名单
  2. 压缩包完整性
  3. 路径穿越拦截（预检 + _safe_join）
  4. 符号链接/特殊文件静默跳过
  5. manifest 合法 JSON + slug 格式正则
  6. 必备模板 7 个全量存在
  7. 单目录/平铺形态自动归一化
  8. 内置主题禁止覆盖；同名自定义主题先删后传
全程临时目录，任何失败不写入 themes/，finally 彻底清理。

启用 / 删除 / 下载

  • 启用：启用前再次强检必备模板；前台即时生效，无需重启。

翻译工作流

模板中用 _() 标记可翻译字符串：

<p>{{ _('仪表盘') }}</p>
<input placeholder="{{ _('搜索文章') }}">

翻译文件位于 app/translations/<lang>/LC_MESSAGES/messages.po（当前提供英文 en）。.po 入库，.mo 不入库，部署前需编译：

# 提取
pybabel extract -F babel.cfg -o app/translations/messages.pot app/
# 更新
pybabel update -i app/translations/messages.pot -d app/translations
# 编译（部署前必做）
pybabel compile -d app/translations
# 新增语种
pybabel init -i app/translations/messages.pot -d app/translations -l ja

每个插件拥有独立翻译域，在 plugins/<slug>/translations/ 下维护 .po/.mo，核心启动时自动发现。

class RecruitJob(db.Model):
    __tablename__ = 'recruit_jobs'

    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    department = db.Column(db.String(100))
    location = db.Column(db.String(200))
    headcount = db.Column(db.Integer, default=1)
    salary = db.Column(db.String(100))
    description = db.Column(db.Text)           # 富文本
    deadline = db.Column(db.DateTime, index=True)
    is_enabled = db.Column(db.Boolean, default=True)
    is_deleted = db.Column(db.Boolean, default=False)
    sort_order = db.Column(db.Integer, default=0)
    created_at = db.Column(db.DateTime, default=datetime.now)
    updated_at = db.Column(db.DateTime, default=datetime.now, onupdate=datetime.now)

    def is_expired(self):
        if self.deadline is None:
            return False
        return datetime.now() > self.deadline

    def is_open(self):
        return self.is_enabled and not self.is_deleted and not self.is_expired()

10. 全站搜索贡献 v2.5.2

插件自有的前台公开内容（岗位、产品等）通过 get_search_provider() 提供一个 SearchProvider 实例，即可进入全站搜索——无需插件自己维护任何索引。核心统一负责：重建索引写入各语言、保存时实时索引（reindex_object('recruit_job', id)）、索引零命中/故障时 SQL 兜底、结果按类型生成详情 URL、插件禁用时清理索引残留。

search.py 的完整骨架（节选自 recruit，产品插件同构）：

from app.utils.search import SearchProvider

class RecruitSearchProvider(SearchProvider):
    type = 'recruit_job'    # 全局唯一的内容类型标识，作为索引 uid 前缀

    def iter_docs(self, locale):
        """后台「重建索引」时逐条产出该语言下的可见文档。"""
        for j in RecruitJob.query.filter_by(is_enabled=True, is_deleted=False):
            doc = self._doc(j, locale)
            if doc: yield doc

    def get_doc(self, obj_id, locale):
        """单条文档（保存时实时索引）；返回 None 表示下架/删除 → 移出索引。"""
        j = RecruitJob.query.filter_by(id=obj_id, is_enabled=True,
                                       is_deleted=False).first()
        return self._doc(j, locale) if j else None

    def sql_search(self, keyword, locale, page=1, per_page=20):
        """索引故障/未建时的 SQL LIKE 兜底，返回 (items, total)。

        非默认语言同时匹配翻译表（含 v2.5.2 的 department/location/salary）。
        """
        ...

    def build_url(self, item):
        """搜索结果 → 详情页链接（伪静态开关两种模式）。"""
        if Setting.get('seo_rewrite_enable') == 'on':
            return f'/job-{item["id"]}.html'
        return url_for('recruit_frontend.job_detail', jid=item['id'])
文档 dict 字段：id, title, summary, content(可含 HTML，核心自动去标签), column_id, column_name, column_slug, published_at。保存/删除/批量上下架时在 admin.py 里调 reindex_object() / unindex_object() 即完成同步；结果项的 url 由核心视图调用 build_url() 统一生成。

14. 常见陷阱

  • 后台模板脚本块是 {% block js %}（不是 scripts），父模板不存在的块名会被静默丢弃。
  • __init__.py 末尾必须 plugin = RecruitPlugin()。
  • 模型 import 必须在 db.create_all() 之前完成。
  • 前台交互页（含验证码/flash）不要接页面缓存。
  • 字典用 g['items'] 而非 g.items（后者命中 dict 方法）。
  • 伪静态路由加入回归测试，确保不劫持核心 /article-<id>.html。
  • SearchProvider 的 iter_docs/get_doc 必须自己过滤下架/删除内容——核心靠 get_doc 返回 None 判断移出索引，过滤漏了下架内容仍会被搜到（v2.5.2）。

升级前必读：四个关键变化

变化说明需做的事
用户权限语义v1.1 所有用户默认超管；v2.0 引入 RBAC升级后审查超管标志并分配角色

升级步骤

为什么必须运行迁移脚本

v2.0 新增 9 张表、旧表补 12 列。仅启动程序无法完成迁移：db.create_all() 只建新表、不给旧表加列；跳过数据回填会让原本隐藏的文章被错误公开。

小版本升级

  • v2.2.x → v2.3.0：无数据库变更，覆盖代码即可；首次启动自动启用表单插件一次。
  • v2.3.x → v2.4.0：覆盖代码 + 装依赖；首次启动自动 stamp Alembic baseline 并执行增量迁移。

数据库迁移 (Alembic) v2.4

v2.4.0 引入 Flask-Migrate（封装 Alembic） 统一管理 schema 版本，支持升级/回滚与插件迁移脚本接入。

旧站自动迁移

  1. 检测旧库（存在核心表但无 alembic_version）
  2. 自动 stamp baseline（标记为 0001，对应 v2.3.0 schema）
  3. 执行增量迁移（0002 建搜索索引表 → 0003 插入搜索设置 → 0004 加 storage 列）
v2.3.x → v2.4.0 无需手动操作，覆盖代码后首次启动自动完成。

CLI 命令

flask db upgrade          # 升级到最新
flask db downgrade -1     # 回滚一版
flask db current          # 查看当前版本
flask db history          # 查看迁移历史
flask db migrate -m "xxx" # 新建迁移脚本（开发用）
生产环境慎用 downgrade；SQLite batch 模式下回滚会重建整表，大表可能耗时较长。

插件迁移钩子

插件通过 PluginBase.get_migration_files() 返回 migrations/versions/ 下脚本路径，核心自动合并到 Alembic version_locations：

def get_migration_files(self):
    mig_dir = Path(self.get_plugin_dir()) / 'migrations' / 'versions'
    return sorted(str(p) for p in mig_dir.glob('*.py') if not p.name.startswith('__'))
无迁移文件的插件仍由 db.create_all() 兜底建表；迁移钩子仅用于表结构变更场景。

全文搜索 v2.4

  • 重建索引：后台「搜索设置」一键重建，未索引前自动回退 SQL LIKE

多语言检索 v2.5.1

开启内容级多语言后，搜索按当前语言检索对应语言的内容，三个后端均已适配：

  • Whoosh：按语言分索引目录 instance/search_index/<locale>/；Meilisearch：按语言分索引 zhycms_articles_<locale>
  • 每篇内容对每种语言写入一份索引，内容经 t_field 解析——有翻译用翻译、无翻译回退默认语言（未翻译内容不会因切语言而搜不到）
  • 搜索结果的标题、摘要、栏目名均随当前语言显示；前台 /search 按 ?lang=xx / session 自动选索引
  • 该语言索引尚未建立时自动回退默认语言索引；i18n 关闭时仅维护默认语言单一索引，行为不变
  • 插件内容同样本地化检索（v2.5.2）：产品的规格参数、岗位的部门/工作地点/薪资待遇均按语言索引与兜底匹配（如英文搜 Model、Shanghai 可命中）
升级到 v2.5.1 后，到后台「系统设置 → 搜索设置」点击一次「重建索引」即可生成各语言索引；内容保存/删除会自动同步全部语言索引，无需手动维护。

插件内容接入搜索（SearchProvider） v2.5.2

插件通过 get_search_provider() 钩子返回一个 SearchProvider 实例，自有内容即可进入全站搜索（官方「产品展示」「招聘管理」已接入）。协议四方法：

方法职责
type内容类型标识（全局唯一，如 product / recruit_job），与 id 组成索引唯一键 uid = "类型:id"
iter_docs(locale)重建索引时产出该语言下全部可见文档
get_doc(id, locale)单条文档（保存时实时索引）；返回 None 表示下架/删除，核心自动移出索引
sql_search(kw, locale, page, per_page)SQL LIKE 兜底检索（索引故障/未建时），需自行匹配翻译表
build_url(item)搜索结果 → 详情页 URL（伪静态两种模式），核心统一分发
完整示例见「插件开发指南 → 全站搜索贡献」。文档以 uid 区分类型，文章与产品/岗位互不覆盖；插件禁用时核心回调 on_disabled() 清理索引残留。产品/岗位保存、删除、批量上下架均实时同步索引。

Redis 缓存与 Session v2.5

v2.5.0 引入 Redis 作为可选的缓存后端与服务端 Session 存储，适合多实例负载均衡场景。未启用 Redis 时回退 SimpleCache + Cookie Session，单机部署零依赖。

自动检测机制

应用启动时检测环境变量 REDIS_URL：

  • 有值且 Redis 可达 → 启用 RedisCache（Flask-Caching）+ 服务端 Session（Flask-Session 存 Redis）
  • 有值但不可达 → 回退 SimpleCache + Cookie Session，日志输出警告
  • 未设置 → SimpleCache + Cookie Session（与 v2.4.x 行为一致）

启用方式

# 源码部署：设置环境变量后启动
export REDIS_URL=redis://127.0.0.1:6379/0
python run.py

# 带密码的 Redis
export REDIS_URL=redis://:yourpassword@127.0.0.1:6379/0

# Docker 部署：install.sh 交互选择启用 Redis
bash docker/install.sh
# 自动在 .env 中写入 REDIS_URL，启动时携带 --profile redis

# docker-compose 手动启动
docker compose --profile mysql --profile redis up -d

后台状态页

后台「系统设置 → Redis 缓存」提供只读状态展示：

  • 已启用（绿色）：显示连接地址，说明 RedisCache + 服务端 Session 已生效
  • 未启用（黄色）：提示安装 Redis 并设置环境变量的步骤
  • 连接失败（红色）：显示错误信息，引导排查 Redis 服务状态与连接参数
Redis 后端在应用启动时初始化，运行时不可切换。修改 REDIS_URL 后需重启应用生效。后台不提供手动开关，避免运行时切换导致缓存与 Session 状态不一致。

安全建议

  • Redis 配置密码（requirepass 或 ACL），REDIS_URL 中携带密码
  • Redis 仅监听内网地址（bind 127.0.0.1 或内网 IP）
  • 生产环境通过防火墙限制 6379 端口访问
  • REDIS_URL 含密码属敏感信息，.env 已在 .gitignore 中排除
