项目简介

ZhyCMS 是一个基于 Flask + SQLAlchemy 的轻量级企业内容管理系统，采用「插件优先、主题驱动」架构，适合搭建企业官网、资讯门户、产品展示站等。

系统严格区分「CMS 自身标识」与「前台企业标识」，后台品牌固定不可改，前台信息独立配置。

从 v1.1 升级：v2.0 起新增 9 张数据表、旧表补 12 列，请先阅读项目根目录 UPGRADE.md 并执行 scripts/upgrade_v2.py 完成迁移。

安装与初始化

环境要求

  • Python 3.9+
  • 数据库：MySQL 5.7+ / PostgreSQL 12+（生产推荐）/ SQLite（仅开发）
生产环境请使用 MySQL 或 PostgreSQL。SQLite 不支持并发写入，容易锁表。

安装步骤

git clone https://gitee.com/pollybird/zhycms
cd zhycms
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python run.py

初始化向导

首次访问 http://127.0.0.1:5000 自动跳转 /admin/setup，需配置：

  • 管理员账号（≥3 字符）与密码（≥6 字符）
  • 数据库类型（MySQL / PostgreSQL / SQLite）
  • 演示数据：不生成 / 制造业 / 服务业 / 教育行业 / 餐饮行业 / Manufacturing (EN) / English Default

数据库选择

类型说明需填写
MySQL生产首选，默认端口 3306主机、端口、库名、用户名、密码
PostgreSQL生产可选，默认端口 5432主机、端口、库名、用户名、密码
SQLite零配置，仅开发/测试无
数据库 URI 优先级：环境变量 ZHYCMS_DB_URI > instance/db_config.json > 默认 SQLite。

# 方式一

Docker 部署 v2.4

官方镜像已发布到 Docker Hub（pollybird/zhycms），开箱即用，无需本地构建。一键安装（推荐，自动生成密钥与密码、配置镜像加速）：

bash docker/install.sh

或手动配置（拉取预构建镜像）：

cp docker/.env.example .env
# 编辑 .env 修改 SECRET_KEY 和数据库密码

# MySQL 8.4 方案（镜像 pollybird/zhycms:mysql）
docker compose -f docker-compose.mysql.yml up -d

# PostgreSQL 16 方案（镜像 pollybird/zhycms:postgresql）
docker compose -f docker-compose.postgresql.yml up -d

# 访问 http://localhost:5000 完成初始化

也可直接拉取镜像：docker pull pollybird/zhycms:mysql（或 :postgresql / :latest，三个 tag 指向同一镜像）。容器启动时自动执行：数据库迁移 → 恢复演示图片 → 编译 i18n → 启动 gunicorn。instance/ 和上传目录通过 volume 持久化。卸载运行 bash docker/uninstall.sh。

用户、角色与权限（RBAC）

后台菜单：用户权限 → 用户列表 / 角色与权限

  • 权限点两级授权：角色勾选权限点，同时控制后台菜单可见性与操作按钮/接口。
  • 多角色并集：一个用户可绑定多个角色，权限取并集。
  • 内容粒度授权：可按栏目授予文章管理权限（如「只管理新闻中心」）。
  • 超级管理员：内置超管不受权限限制；未授权菜单不可见，接口返回 403 并记录审计。
角色删除前自动解除用户绑定；用户禁用后立即无法登录，已有会话下次请求时失效。

内容工作流与版本管理

状态流转

草稿(draft) ──提交审核──→ 待审核(pending) ──审核通过──→ 已发布(published)
    ↑                          │
    └────────驳回──────────────┘ 已驳回(rejected)
  • 无发布权限的作者只能保存草稿并提交审核；有权限的编辑可直接发布。
  • 待审核文章仅具备审核权限的用户可见，前台不展示。
  • 驳回时必须填写原因，作者可修改后重新提交。

版本快照

文章每次保存自动生成版本快照，支持查看差异与一键还原（还原动作本身也生成新版本，可安全撤销）。

页面缓存与图片 ALT

  • 页面缓存：基于 Flask-Caching，首页/栏目/文章独立 TTL（默认 3600/1800/7200 秒）；内容变更后自动清理对应缓存。
  • 图片默认 ALT：为缺失或空 alt 的 <img> 自动填充默认值。
  • 图片 ALT 批量管理：后台工具页，批量排查全站图片 ALT 缺失情况。

安全加固

登录防暴破

  • 连续输错密码 5 次（可配置）自动锁定 10 分钟（可配置），锁定期内正确密码也被拒绝。
  • 登录页图形验证码：错误不累计密码失败次数。
  • 异地 IP 登录提醒：检测到不同城市 IP 时顶部展示一次性安全横幅。
  • 所有登录行为写入登录日志。

后台路由前缀

系统设置 → 后台安全 中修改前缀（如 admin → manage-x8y2）后即时生效，无需重启。旧前缀立即 404，页内跳转自动使用新前缀。忘记路由可删除 instance/admin_config.json 恢复默认。

上传安全与图片优化

后台菜单：系统设置 → 上传安全，默认全部开启：

  • 后缀 + MIME 双重校验：检查文件真实内容（magic bytes），伪装成图片的脚本直接拒绝。
  • SHA-256 内容去重：相同内容只存一份，多处引用自动计数。
  • 图片自动压缩 + 缩略图：JPG/PNG 压缩（默认质量 80）并生成 300px 缩略图。
  • 单文件上限默认 10MB，可配置。

审计日志

后台菜单：审计日志。登录/登出、配置变更、内容增删改、备份恢复、权限调整等关键操作全量留痕，记录操作人、IP、时间、类型与详情；支持按模块、操作类型、操作人与时间范围检索。

主题模板开发 API v2.6.4 全量整理

前台基于 Jinja2 + Bootstrap 4.6，采用「多主题 + 栏目级模板」双层机制。内置 8 套主题：default / blue / manufacturing / service / default_en / manufacturing_en / education / catering。权威文档见仓库 docs/THEME_TEMPLATE_API.md。

机制与解析链

主题覆盖  themes/<active_theme>/<name>.html
   ↓ 不存在
插件自带  plugins/<slug>/templates/<name>.html（如 banner/hero_carousel.html）
   ↓ 不存在
default 主题兜底  themes/default/<name>.html

创建新主题：cp -r themes/default themes/green → 修改 css/style.css 与 manifest.json（slug 需与目录名一致）→ 后台 系统设置 → 主题管理 启用。主题自动发现，无需代码注册。

base.html 契约

所有页面通过 {% extends theme_base %} 继承当前主题 base.html，必须提供 5 个 block：

{% block title %}{{ seo.title }}{% endblock %}      {# <title>，拼接 site_settings.site_name #}
{% block css %}{% endblock %}                        {# 子页附加样式 #}
{% block locale_switcher %}…{% endblock %}           {# 语言切换器（子页可整体替换） #}
{% block content %}{% endblock %}                    {# 页面主体 #}
{% block js %}{% endblock %}                         {# 子页附加脚本 #}

标准骨架要素：样式（Bootstrap 4.6.2 / Font Awesome 5.15.4 / 主题 CSS）、SEO meta（seo.keywords / seo.description）、导航（末尾 {{ member_user_menu() }} + 语言切换器）、搜索框（action="{{ url_for('frontend.search') }}" 参数名 q）、flash 消息、统计代码位（analytics_head()/analytics_body()）、页脚（footer_copyright + ICP 碎片）。

REST 内容 API v2.2

前缀 /api/v1，只读端点，供小程序/Headless 前端消费。

配置与鉴权

  • 总开关（api_enable）：关闭后所有端点返回 404。
  • 鉴权模式（api_auth_mode，v2.6.3）：token（仅 X-API-Token）/ jwt（仅 Bearer JWT）/ both（默认，优先 JWT 回退 Token）。
  • 静态 Token（api_token）：非空时要求请求头 X-API-Token。
  • JWT 登录（v2.6.3）：POST /api/v1/auth/login 用用户名密码换取 access_token（15min）+ refresh_token（7d），请求头 Authorization: Bearer <access_token>。
  • JWT 刷新：POST /api/v1/auth/refresh（Header 带 refresh_token）换新 access_token。
  • 速率限制（v2.6.3，api_rate_limit_enable）：登录 5 次/分钟、只读 GET 120 次/分钟，超限返回 429。
  • CORS（api_cors_origins）：* 或逗号分隔域名。
  • 缓存 TTL（api_cache_ttl）：默认 300 秒。

    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    content = db.Column(db.Text)                # 富文本，前台 |safe 输出
    status = db.Column(db.String(10), default=STATUS_ON)
    sort_order = db.Column(db.Integer, default=0)
    is_deleted = db.Column(db.Boolean, default=False)
    created_at = db.Column(db.DateTime, default=datetime.now)

    @classmethod
    def visible(cls):
        return (cls.query.filter_by(is_deleted=False, status=cls.STATUS_ON)
                .order_by(cls.sort_order.desc(), cls.id.desc()))

5. 数据模型与开发要点

  • 自动建表：启用时 db.create_all() 幂等补齐；模型必须在插件 __init__.py 顶部导入。
  • schema 变更：新字段需在 plugins/<slug>/migrations/versions/ 放 Alembic 脚本，核心启动自动合并。
  • 多语言：主表存默认语言 + <table>_translations 翻译表（locale + CASCADE 外键）；前台 t(obj,'field')、Python t_field，空回退主表。
  • 后台：三层守卫（启用 → 权限 → 业务校验）；模板继承 admin/base.html，脚本块用 {% block js %}。
  • 前台：视图套启用门控；模板函数返回 dict/list 并声明 fallback；含验证码/flash 的交互页不接页面缓存。
  • 伪静态：详情页同时提供动态路由与 /<前缀>-<id>.html；关闭伪静态时伪静态路由 404；不得与核心 article- 前缀冲突。

9. 常见陷阱

  • 忘写 plugin = MyPlugin() → 核心识别不到插件。
  • 模型导入晚于 db.create_all() → 表缺失，SQL 报 1146/no such table。
  • 后台路由自建蓝本 → 后台前缀切换后路由失效。
  • 模板里 {{ j.url }} 而模型无该属性 → Jinja 静默输出空 href（应用注册的 URL 函数）。
  • get_jinja_fallbacks() 漏声明 → 禁用插件后主题渲染报错。
  • 交互页接了页面缓存 → 验证码/flash 错乱、用户间串数据。
  • 伪静态前缀与核心 article- 冲突 → 路由劫持。
  • SearchProvider 未过滤下架内容 → 已下架内容仍可被搜到。
  • 后台模板用 scripts block → 脚本不执行（正确为 {% block js %}）。
  • 字典取值 g.items 命中 dict 方法 → 应为 g['items']。

def get_migration_files(self):
    mig_dir = Path(self.get_plugin_dir()) / 'migrations' / 'versions'
    return sorted(str(p) for p in mig_dir.glob('*.py') if not p.name.startswith('__'))

对象存储 OSS v2.4

官方内置插件 oss_storage，支持阿里云 OSS / 腾讯云 COS / 七牛云 Kodo。默认本地存储、零行为变化：升级后自动启用但不配置凭证不产生任何云端调用。

架构

  • 核心抽象层 app/utils/storage.py：定义 StorageDriver 协议与本地驱动；上传入口 save_upload_file() 先在本地完成校验/压缩，再发布到当前驱动。
  • 云驱动在插件中：SDK 可选依赖、运行时懒加载，未安装时配置页给出 pip install 指引。
  • 文件归属：uploaded_files.storage 列标记文件存于哪个驱动；切换驱动后历史 URL 不受影响。
  • 禁用回退：禁用插件时自动把存储驱动重置为本地。

配置步骤

  1. 安装对应 SDK：pip install oss2 / cos-python-sdk-v5 / qiniu
  2. 云厂商控制台创建 Bucket，使用 RAM 子账号（仅授予目标 Bucket 读写权限）
  3. 后台 系统设置 → 对象存储 填写凭证并连接测试

一键迁移

配置页提供 dry-run 预览（待传文件数、内容引用链接数）与一键执行：

  • 逐文件上传，云端已存在自动跳过（可中断、可重入）
  • 上传成功后批量改写内容中的本地链接为云域名
  • 本地原文件保留不删；uploads/demo/ 不迁移

安全设计

  • 云端上传失败显式报错，不静默回退本地
  • 备份恢复文件强制存本地（storage_scope='local'）
  • 凭证存数据库 settings 表，不写入仓库文件
  • 七牛云必须绑定自有 CDN 域名（默认下载域名 30 天过期）

Redis 缓存与 Session v2.5

v2.5.0 引入 Redis 作为可选的缓存后端与服务端 Session 存储，适合多实例负载均衡场景。未启用 Redis 时回退 SimpleCache + Cookie Session，单机部署零依赖。

自动检测机制

应用启动时检测环境变量 REDIS_URL：

  • 有值且 Redis 可达 → 启用 RedisCache（Flask-Caching）+ 服务端 Session（Flask-Session 存 Redis）
  • 有值但不可达 → 回退 SimpleCache + Cookie Session，日志输出警告
  • 未设置 → SimpleCache + Cookie Session（与 v2.4.x 行为一致）

启用方式

# 源码部署：设置环境变量后启动
export REDIS_URL=redis://127.0.0.1:6379/0
python run.py

# 带密码的 Redis
export REDIS_URL=redis://:yourpassword@127.0.0.1:6379/0

# Docker 部署：install.sh 交互选择启用 Redis
bash docker/install.sh
# 自动在 .env 中写入 REDIS_URL，启动时携带 --profile redis

# 独立 compose 文件：取消注释文件中的 redis 服务块与 redis_data 卷
# docker-compose.mysql.yml 或 docker-compose.postgresql.yml 内已预置（默认注释）
# 也可用通用编排文件：
docker compose --profile mysql --profile redis up -d

后台状态页

后台「系统设置 → Redis 缓存」提供只读状态展示：

  • 已启用（绿色）：显示连接地址，说明 RedisCache + 服务端 Session 已生效
  • 未启用（黄色）：提示安装 Redis 并设置环境变量的步骤
  • 连接失败（红色）：显示错误信息，引导排查 Redis 服务状态与连接参数
Redis 后端在应用启动时初始化，运行时不可切换。修改 REDIS_URL 后需重启应用生效。后台不提供手动开关，避免运行时切换导致缓存与 Session 状态不一致。

安全建议

  • Redis 配置密码（requirepass 或 ACL），REDIS_URL 中携带密码
  • Redis 仅监听内网地址（bind 127.0.0.1 或内网 IP）
  • 生产环境通过防火墙限制 6379 端口访问
  • REDIS_URL 含密码属敏感信息，.env 已在 .gitignore 中排除

缓存与 Redis

  • 日志 [Redis] 连接失败，回退 SimpleCache：自动降级仍可用；多 worker 部署建议修复 REDIS_URL（格式 redis://:密码@host:6379/0）。
  • 改内容/设置前台不生效：后台保存会自动清缓存，直改数据库不会；手工清空可重启应用或 redis-cli FLUSHDB。
  • 主题切换后样式仍旧：确认 ≥ v2.6.3（缓存键含主题 + 切换清缓存已修复）。
  • 多 worker 登录态丢失：Session 依赖 Redis；回退 Cookie Session 时需固定 SECRET_KEY。

主题与插件

  • TemplateNotFound：查双后缀拼接错误 → 文件是否在正确目录 → 自定义主题缺必备模板被拒启用 → default 主题文件是否完整。
  • 主题上传被拒：按 8 步校验排查（格式/完整性/路径穿越/symlink/manifest/必备模板/形态归一化/覆盖保护），报错指明失败步骤。
  • 插件启用失败：v2.6.4 按 min_core_version → requires → extends 强校验，按提示升级核心或先启用依赖；禁用被依赖插件会被反向拦截并列出依赖方。
  • 插件「加载失败」：启动日志该插件的 traceback 即原因（模型字段不匹配/依赖缺失/忘写 plugin = XxxPlugin()）。
  • 删除需验证码：危险操作独立一次性验证码（/captcha/delete-confirm）；内置或启用中的对象拒绝删除。

伪静态与路由

  • 伪静态第 2 页 404：Nginx 需把 *.html 转发到应用（try_files $uri $uri/ @app;）；动态形式 /column/<slug>?page=2 始终兼容 200，可用来区分是 Web 服务器转发问题还是应用问题。
  • /article-5.html 被劫持：article- 前缀规则优先级最高；排查插件是否注册了同名冲突路由。
  • 改后台前缀后打不开：修改即时生效；使用了保留字（如 form）会与前台冲突，改回即可（settings 表 admin_prefix）。
  • robots.txt / sitemap.xml / favicon.ico 404：三者在初始化拦截/维护模式中豁免，正常始终可访问；404 多为应用没启动成功。

上传与搜索

  • 中文文件名后缀丢失：上传类型判断从原始文件名取后缀（已修复）；自查是否绕过核心 save_upload_file()。
  • 上传 413：调大 Nginx client_max_body_size 与后台上传限制。
  • 图片不显示：查 app/static/uploads/ 写权限（Docker uid 1000）；缩略缓存 instance/image_cache/ 损坏可清空重建。
  • 搜不到新内容：保存时实时索引，异常时自动 SQL 兜底；连兜底都无结果查文章 status/is_deleted/栏目启用。
  • 搜索报错：后台重建索引；必要时删 instance/search_index/ 对应语言目录再重建（无数据风险）。

Docker 专项

  • 反复重启 database not reachable after 60s：entrypoint 等库 60 秒超时；检查 db 健康状态与 ZHYCMS_DB_URI，首次初始化慢需等待。
  • Access denied（数据卷由旧密码初始化）：改 .env 密码不影响已初始化卷。方案 A：旧密码重装（install.sh 选复用已有数据）；方案 B（清数据）：docker compose --profile <mysql|mariadb|postgres> down -v。
  • Permission denied 写 instance/：entrypoint root 自愈 chown 1000:1000 后降权；仍失败查 SELinux/挂载参数。
  • 镜像拉取超时：install.sh 内置多源回退（daocloud → 1ms.run → xuanyuan.me → hub.rat.dev，每站重试 2 次）。
  • unhealthy：docker exec <容器> curl -s http://localhost:5000/healthz 看返回。

备份与快速诊断

  • 内置备份存 instance/backups/（数据库 + uploads）；手动兜底：mysqldump / pg_dump / SQLite 文件 + uploads + instance 目录。
  • 恢复后 alembic_version 随库走，恢复旧库后启动新代码自动 upgrade head 补齐。
  • 诊断命令：curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:5000/healthz；docker compose --profile mysql logs -f app；缩略缓存 rm -rf instance/image_cache/* 可安全清空。
