zhycms 使用手册 v2.2.0

基于 Flask 的轻量级企业网站 CMS — 目录结构 · 安装初始化 · 部署 · 权限与安全 · 备份运维 · 消息通知 · SEO 性能 · 模板制作教程 · REST 内容 API · 插件机制与开发指引 · v1.1→v2.0 升级迁移

项目简介

zhycms 是一个基于 Flask + SQLAlchemy 的轻量级内容管理系统，内置多主题模板引擎、栏目级模板选择、自定义字段、表单收集、SEO 优化等能力，适合搭建企业官网、资讯门户、产品展示站等。

v2.0 围绕「企业级安全、可控、可运维」新增八大模块：RBAC 权限体系、审计日志、内容工作流、备份恢复、登录安全加固、上传安全与图片优化、表单消息通知、SEO 与站点性能。

从 v1.1 升级：v2.0 新增 9 张数据表、旧表补 12 列与 4 个依赖，请先阅读项目根目录的 UPGRADE.md 升级迁移指南，并执行幂等迁移脚本 scripts/upgrade_v2.py 完成数据库迁移（仅启动程序无法完成迁移，且可能把原本隐藏的文章错误公开）。

特性一览

  • 多主题模板系统：前台模板按主题组织，后台一键切换。内置 default、blue 两套通用聚合主题，以及 manufacturing（制造业）、service（服务业）两套行业专用主题。
  • 演示数据一键生成：初始化时可选「制造业」或「服务业」示例，自动生成栏目、文章、碎片、友情链接与演示图片并切换主题。
  • CMS 标识与企业标识分离：后台 CMS 名称/版权固定不可改，前台网站名称/版权可独立配置。
  • 栏目级模板选择：每个栏目可指定独立的列表页/内容页/单页模板，未指定自动回退默认。
  • 自定义字段：栏目和文章支持自定义字段（文本/富文本/图片/文件/URL/数字等）。
  • 表单收集：可视化表单设计，支持文本/手机/邮箱/单选/多选/文件上传，带图形验证码防刷，提交数据可导出；v2.0 支持提交后邮件/企业微信实时通知。
  • SEO 优化 / 碎片管理 / 友情链接 / 图片上传 / 验证码登录 / 首次初始化引导。
  • v2.0 企业级能力：RBAC 角色权限、审计日志、内容工作流与版本还原、数据库备份恢复、登录防暴破、上传内容安全校验、伪静态与页面缓存。

二、安装与初始化

环境要求

  • Python 3.9+
  • SQLite（默认，开箱即用）或 MySQL / PostgreSQL

安装步骤

# 克隆代码
git clone <your-repo-url> zhycms
cd zhycms

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

# 安装依赖（国内建议使用镜像源加速）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
# 清华源： -i https://pypi.tuna.tsinghua.edu.cn/simple

# 启动开发服务器
python run.py
requirements.txt 已内置 MySQL 驱动 PyMySQL 与 PostgreSQL 驱动 psycopg2-binary，初始化时选择对应数据库类型即可，无需额外安装。

初始化向导

浏览器访问 http://127.0.0.1:5000，首次访问会自动跳转到 /admin/setup 初始化向导。向导中需要填写：

  • 管理员账号（至少 3 个字符）与密码（至少 6 个字符，需二次确认）
  • 数据库类型：MySQL / PostgreSQL（生产推荐）/ SQLite（仅开发/测试，见下）
  • 演示数据：不生成 / 制造业 / 服务业

提交后系统会创建管理员、写入默认设置，并按选择生成演示数据，随后跳转登录页。

数据库选择

生产环境请选择 MySQL 5.7+ 或 PostgreSQL 12+：SQLite 不支持并发写入，正式站点使用容易锁表，仅适用于开发与测试。
类型说明需要填写
MySQL （生产推荐）生产首选（5.7+），连接已有 MySQL 服务，默认端口 3306主机、端口、数据库名、用户名、密码
PostgreSQL （生产推荐）生产可选（12+），连接已有 PostgreSQL 服务，默认端口 5432主机、端口、数据库名、用户名、密码
SQLite（仅开发/测试）默认选项，直接生成 instance/zhycms.db 文件，零配置；不支持并发写入，不要用于生产环境无
选择 MySQL/PostgreSQL 时，向导会先测试连接，成功后才将连接信息写入 instance/db_config.json 并热切换数据库引擎；若切换失败会自动回滚到原库，保证应用可继续运行。
数据库 URI 解析优先级（见 app/config.py）：
环境变量 ZHYCMS_DB_URI > instance/db_config.json（初始化向导所存） > 默认 SQLite。

三、部署

开发模式

python run.py
# 监听 0.0.0.0:5000，默认开启 DEBUG，代码/模板改动自动重载

生产部署

# 直接运行（关闭 DEBUG）
ZHYCMS_ENV=production ZHYCMS_SECRET_KEY=your-secret python run.py

# 或使用 gunicorn（推荐）
gunicorn -w 4 -b 0.0.0.0:5000 "run:app"
生产环境注意：务必通过 ZHYCMS_SECRET_KEY 设置自定义会话密钥；建议在 gunicorn 前置 Nginx 反向代理并托管 app/static/ 静态资源。

环境变量

变量默认值说明
ZHYCMS_ENVdevelopment配置模式：development / production
ZHYCMS_SECRET_KEY内置默认值会话加密密钥，生产环境必须修改
ZHYCMS_DB_URIsqlite:///instance/zhycms.db数据库 URI，可换成 MySQL/PostgreSQL；优先级最高
v2.1 起环境变量前缀统一为 ZHYCMS_（与项目名一致）；旧前缀 ZHOCMS_（v2.1 前的拼写差异）仍被识别作为兼容回退，但将在未来版本移除，建议尽快改用新前缀。

四、CMS 标识与网站标识

系统严格区分「CMS 自身标识」与「前台企业标识」四个概念，避免演示数据或用户配置误改后台品牌：

概念显示位置取值来源可否修改
CMS 名称后台顶栏 / 登录页 / 后台标题Setting.CMS_NAME 固定常量❌ 不可改
后台版权后台底部Setting.CMS_COPYRIGHT 固定常量❌ 不可改
网站名称前台导航 / 首页 / 页脚Setting 'site_name'（企业名）✅ 网站设置可改
前台版权前台底部Setting 'footer_copyright'✅ 网站设置可改
约定：后台模板一律使用 cms_name / cms_copyright（由 app/__init__.py 的上下文处理器注入），不得读取 site_settings.site_name / site_settings.footer_copyright（那是前台企业信息）；前台模板则相反。

六、模板制作教程

zhycms 前台采用 多主题 + 栏目级模板 的双层机制，主题可在网站设置一键切换，栏目可单独指定列表/内容/单页模板。模板基于 Jinja2 + Bootstrap 4。

1. 主题目录结构

所有主题存放在 app/frontend/templates/themes/ 下，每个主题是一个独立目录，目录名即主题名：

themes/default/
├── base.html            # 基础布局（必须）
├── index.html           # 首页（必须）
├── list.html            # 列表页默认模板（必须）
├── article.html         # 文章详情默认模板（必须）
├── page.html            # 单页默认模板（必须）
├── list_card.html       # 卡片式列表（可选，栏目备选模板）
├── column_children.html # 父栏目展示子栏目列表
├── search.html          # 搜索结果页
├── form.html            # 表单提交页（含验证码）
├── form_closed.html     # 表单关闭提示页
├── closed.html          # 站点关闭提示页
├── 404.html
└── 500.html

必备模板

文件用途
base.html全站基础骨架，所有页面通过 {% extends theme_base %} 继承
index.html站点首页
list.html列表栏目默认列表页（名称固定 list）
article.html文章详情默认页（名称固定 article）
page.html单页栏目默认页（名称固定 page）
404.html / 500.html错误页
closed.html站点关闭时展示

可选模板（栏目级备选）

凡以 list、article、page 开头的 .html 文件，会自动出现在后台栏目编辑页的下拉选项中：

  • list_xxx.html → 列表栏目可选用
  • article_xxx.html → 文章详情页可选用
  • page_xxx.html → 单页栏目可选用
受保护模板（即使以上述前缀开头也不会列为栏目备选，因为它们是系统级模板）：
base、404、500、closed、form_closed、index、search、column_children、form

2. 创建一个新主题

以创建名为 green 的绿色风格主题为例：

步骤 1：复制默认主题作为起点

cp -r app/frontend/templates/themes/default app/frontend/templates/themes/green

步骤 2：修改 base.html 中的样式

/* 主题色：绿色 */
.navbar { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%) !important; }
.footer { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%); color:#e8f5e9; }
.card-header { background:#2e7d32; color:#fff; }
.btn-primary { background-color:#2e7d32; border-color:#2e7d32; }
a { color:#2e7d32; } a:hover { color:#1b5e20; }

步骤 3：在后台启用

进入 后台 → 网站设置 → 前台主题，下拉框会自动出现 green 选项，选中保存即可。

主题的发现是自动的：扫描 themes/ 下所有子目录，无需在代码中注册。

3. 模板继承与 theme_base

所有页面模板通过 {% extends theme_base %} 继承当前主题的 base.html，而不是写死路径：

{% extends theme_base %}
{% block title %}页面标题{% endblock %}
{% block content %}
  页面内容
{% endblock %}

theme_base 由上下文处理器注入，值类似 themes/default/base.html，切换主题时自动找到对应的 base.html。

base.html 必须提供的 block

Block 名用途
title<title> 标签内容
css页面级 CSS（在 <head> 内）
content主体内容
js页面级 JS（在 </body> 前）

4. 全局模板变量

以下变量在所有前台模板中可直接使用（由 app/__init__.py 的 context_processor 注入）：

变量类型说明
site_settingsdict站点设置，含前台企业标识：site_name、site_subtitle、site_logo、footer_copyright 等
site_fragmentsdict碎片内容，键为碎片 slug，值为 Fragment 对象（访问 .value）

视图函数传入的常用变量

  • 首页 index.html：nav、first_page、latest_articles、friend_links、seo；行业主题另有 about_col、products_col/products、services_col/services、news_col/news、cases_col/cases（按 slug 约定收集，通用主题忽略）
  • 列表页 list.html：column、articles、pagination、nav、seo
  • 文章详情 article.html：column、article、fields、latest_articles、prev_article、next_article、nav、seo
  • 单页 page.html：column、nav、seo
  • 表单 form.html：form、fields、nav、seo
  • 搜索 search.html：keyword、results、nav、seo
  • 父栏目 column_children.html：column、children、nav、seo

6. URL 生成与自定义过滤器

{{ url_for('frontend.index') }}                                   {# 首页 #}
{{ url_for('frontend.column_detail', slug=column.slug) }}         {# 栏目页 #}
{{ url_for('frontend.column_detail', slug=column.slug, page=2) }} {# 带分页 #}
{{ url_for('frontend.article_detail', slug=column.slug, aid=article.id) }} {# 文章 #}
{{ url_for('frontend.form_submit', slug=form.slug) }}             {# 表单 #}
{{ url_for('frontend.search') }}                                  {# 搜索 #}

伪静态分页助手（v2.0）

v2.0 起全局注入 frontend_pager_url(column, page)：SEO 高级中开启伪静态时自动输出 /{slug}-{N}.html（第 1 页为 /{slug}.html），关闭时输出 /column/{slug}?page=N。自定义列表模板的分页链接请统一使用该助手，不要写死动态 URL：

<a href="{{ frontend_pager_url(column, pagination.prev_num or 1) }}">&laquo; 上一页</a>
{% for p in pagination.iter_pages() %}
  <a href="{{ frontend_pager_url(column, p) }}">{{ p }}</a>
{% endfor %}
<a href="{{ frontend_pager_url(column, pagination.next_num or pagination.page) }}">下一页 &raquo;</a>
文章详情页可直接使用 url_for('frontend.article_detail', ...)，系统会自动识别；伪静态开启时也可直接输出 /{{ article.id }}.html。
过滤器用途示例
date格式化日期{{ article.published_at|date }} → 2026-08-06
datetime格式化日期时间{{ article.published_at|datetime }} → 2026-08-06 22:30
truncate_text截断文本{{ article.summary|truncate_text(80) }}

7. 制作栏目级备选模板

以制作「卡片式列表模板」为例。步骤 1：在主题目录下创建以 list 开头的文件 list_card.html。步骤 2：编写模板内容（继承 theme_base，遍历 articles 渲染卡片，用 pagination 生成分页）。步骤 3：进入后台栏目编辑页，「列表页模板」下拉框会出现 list_card 选项，选中保存即可。

前缀对应栏目模板类型出现位置
list_*列表页模板列表栏目的「列表页模板」下拉
article_*内容页模板列表栏目的「内容页模板」下拉
page_*单页模板单页栏目的「单页模板」下拉
若栏目指定的模板在当前主题中不存在（如切换主题后新主题没有该模板），系统会自动回退到默认模板（list / article / page），不会报错。

七、用户、角色与权限（RBAC）

后台菜单 用户权限 → 用户列表 / 角色与权限（v2.0 新增）。

权限模型

  • 权限点两级授权：角色可勾选一组权限点，同时控制后台菜单可见性与操作按钮/接口（如文章发布、备份恢复、配置修改、用户管理）。
  • 多角色并集：一个用户可绑定多个角色，最终权限为所有角色权限点的并集。
  • 内容粒度授权：支持按栏目授予文章管理权限（如「只管理新闻中心」），实现内容运营岗位的最小权限分配。
  • 超级管理员：内置超管不受任何权限限制，普通用户未授权的菜单不可见、直接访问接口返回 403 并记录审计日志。
角色删除前会先解除用户绑定；用户被禁用后立即无法登录，已有会话在下一次请求时失效。

八、内容工作流与版本管理

文章编辑流程从 v1.1 的「直接发布」升级为可审核的工作流（v2.0 新增）：

状态流转

草稿(draft) ──提交审核──> 待审核(pending) ──审核通过──> 已发布(published)
    ▲                          │
    └────────驳回──────────────┘ 已驳回(rejected，需填写驳回原因)
  • 无发布权限的作者只能保存草稿并提交审核；有发布权限的编辑可直接发布。
  • 待审核文章只有具备审核权限的用户可见可操作，前台不展示。
  • 驳回时必须填写原因，作者可在文章列表看到驳回原因并修改后重新提交。

版本快照

  • 文章每次保存自动生成版本快照，记录标题/正文/摘要等完整内容与操作时间。
  • 文章编辑页 版本历史 中可查看任意两个版本的差异，支持一键还原到指定版本（还原动作本身也会生成新版本，可安全撤销）。

九、备份与恢复

后台菜单 备份运维 → 备份列表（v2.0 新增），备份文件存放于 instance/backups/。

备份方式

方式适用说明
MySQL 逻辑备份MySQL / MariaDB调用 mysqldump 导出全库结构与数据，gzip 压缩为 .sql.gz
PostgreSQL 备份PostgreSQL调用 pg_dump，同样 gzip 压缩
JSON 备份任意数据库与数据库类型无关的通用格式，适合小站点迁移或跨库切换

操作说明

  • 立即备份：选择备份方式一键执行，完成后列表显示文件名、大小、耗时与操作人。
  • 下载：将备份文件下载到本地异地保存。
  • 恢复：从备份文件一键恢复。恢复前系统自动提交并释放数据库连接池，避免 DROP TABLE 时被自身连接的元数据锁阻塞。
  • 删除：清理过期备份文件与记录。
恢复前务必确认：恢复操作会用备份内容覆盖当前数据库全部数据，且要求运行环境具备 mysqldump / pg_dump 命令（JSON 方式除外）。建议先下载一份当前备份再执行恢复。

后台菜单 系统设置 → 消息通知（v2.0 新增）。配置后，前台表单每收到一条提交都会实时推送到指定渠道。

邮件通知

配置项说明
SMTP 服务器 / 端口 / SSL如 smtp.exmail.qq.com / 465 / 开启

十一、SEO 与站点性能

后台菜单 系统设置 → SEO 高级（v2.0 新增）。

伪静态 URL

开启伪静态后，前台自动支持以下 URL（关闭后这些地址返回 404，动态 URL 照常可用）：

URL含义等价动态 URL
/about.html栏目页（第一页）/column/about
/about-2.html栏目列表页第 2 页/column/about?page=2
/article-12.html文章详情/column/{slug}/article/12
  • 页面中的栏目、文章、分页链接会同步输出为伪静态格式（第 1 页输出 /about.html，不带 -1 后缀；第 N 页输出 /about-N.html）。
  • 访问 /about-1.html 会 301/302 规范化到 /about.html，避免搜索引擎收录重复页面。
  • 含连字符数字的栏目 slug（如 news-2024）可正确解析，不会被误切分为栏目 + 页码。
  • 开关即时生效，无需重启；自定义模板请使用全局助手 frontend_pager_url(column, page) 生成分页链接（见模板教程第 6 节）。

sitemap 与 robots

  • sitemap.xml：自动收录全部栏目与文章，栏目页/文章页的更新频率（changefreq）与优先级（priority）独立配置；伪静态开启时输出 .html 地址。
  • robots.txt：内置默认规则（跟随后台前缀 Disallow、屏蔽 /form/ 表单地址、声明 Sitemap），支持追加自定义规则；后台前缀变更后默认规则自动跟随。

页面缓存与图片 ALT

  • 页面缓存：基于 Flask-Caching，首页 / 栏目列表页 / 文章详情页可分别设置 TTL（默认 3600 / 1800 / 7200 秒）；发布、编辑、删除内容后自动清理对应缓存，不会出现「改了前台不更新」。
  • 图片默认 ALT：设置默认值后，前台渲染时自动为缺失或空 alt 的 <img> 填充（已设置 alt 的保留原值），提升无障碍访问与图片 SEO。
  • 图片ALT批量管理（系统设置 → 图片ALT批量管理）：后台工具页，批量排查全站文章/单页正文中的图片 ALT 缺失情况。

十二、安全加固

登录防暴破（v2.0）

  • 连续输错密码达到阈值（默认 5 次）自动锁定账号，锁定期内即使密码正确也会被拒绝；锁定时长默认 10 分钟，到期自动解锁。次数与时长均可在 系统设置 → 后台安全 中调整。
  • 登录页配备图形验证码；验证码错误会记录失败日志但不累计密码失败次数（验证码先于密码验证）。
  • 异地登录提醒：检测到与上次登录不同的 IP 城市时，登录成功后顶部展示一次性安全提醒横幅（可在设置中关闭）。
  • 所有登录行为（成功/失败/锁定）均写入 登录日志（系统设置 → 登录日志）。

后台路由前缀即时生效（v2.0）

系统设置 → 后台安全 中修改后台前缀（如 admin → manage-x8y2）后，v2.0 起即时生效、无需重启服务：新前缀立即可访问，旧前缀立即失效（404），后台页内跳转自动使用新前缀。历史前缀保存在 instance/admin_config.json，忘记路由时删除该文件可恢复默认 admin。

上传安全与图片优化（v2.0）

后台菜单 系统设置 → 上传安全，以下能力默认开启：

  • 后缀 + MIME 双重校验：除了校验后缀白名单，还检查文件真实内容（magic bytes）；伪装成 .jpg 的 PHP/Shell/可执行文件（含 <?php、#!、MZ、ELF 等特征）直接拒绝；图片后缀强制要求内容为真实图片。
  • SHA-256 内容去重：相同内容的文件全局只保存一份，多处引用自动计数（删除引用计数归零才真正清理磁盘）。
  • 图片自动压缩 + 缩略图：JPG/PNG 上传后自动压缩（质量默认 80，可调）并生成 300px 宽缩略图（可调），显著降低磁盘与流量开销。
  • 单文件大小上限默认 10MB，可配置；超限直接拒绝并给出明确提示。
  • 所有上传文件建立统一索引（原始大小/压缩后大小/宽高/缩略图路径/引用计数），可在后台查看与管理。

审计日志（v2.0）

后台菜单 审计日志：登录/登出、配置变更、内容增删改与发布审核、备份恢复、用户与权限调整等关键操作全量留痕，记录操作人、IP、操作时间、操作类型与详情；支持按模块、操作类型、操作人与时间范围检索，为安全追溯提供依据。

十三、v1.1 → v2.0 升级迁移

正在运行 v1.1 及更早 1.x 版本的站点升级到 v2.0 前，请务必完整阅读项目根目录的 UPGRADE.md（升级迁移指南）。本章为速览。

升级前必读：四个关键变化

变化说明需要做的事
用户权限语义v1.1 所有用户默认超级管理员；v2.0 引入 RBAC，新建用户默认无权限升级后到「用户权限 → 用户列表」收紧非管理员的超管标志并分配角色
文章状态机is_enabled 开关升级为工作流状态（迁移自动回填，前台展示效果不变）无需手工处理；确认隐藏文章升级后仍不可见
登录安全默认启用失败 5 次锁定 10 分钟、图形验证码、异地提醒告知全体后台用户；弱密码账号建议一并改密
上传行为变化MIME 双重校验/SHA-256 去重/压缩缩略图默认开启，仅影响新上传伪装成图片的脚本将无法上传

升级步骤速览

# 0. 备份站点目录与数据库（必做！）

# 1. 停服并更新代码到 v2.0
git fetch && git checkout v2.0

# 2. 更新依赖（新增 4 个；Linux 需补系统库 libmagic）
pip install -r requirements.txt
sudo apt install -y libmagic1        # Debian/Ubuntu

# 3. 执行数据库迁移（幂等脚本，可重复运行）
.venv/bin/python scripts/upgrade_v2.py

# 4. 启动服务，按 UPGRADE.md 的验证清单逐项核对

为什么必须运行迁移脚本

v2.0 新增 9 张数据表、旧表补 12 列并回填文章状态。仅启动程序无法完成迁移：db.create_all() 只建新表、不会给旧表加列；若跳过数据回填，ALTER ADD COLUMN ... DEFAULT 'published' 会让原本隐藏的文章被错误公开。迁移脚本已通过版本记录保证幂等，可安全重复执行。

升级后验证要点

  • 原本隐藏的文章（is_enabled=0）升级后仍然不可见
  • 后台登录正常（需输入图形验证码）；连续错 5 次密码会锁定 10 分钟
  • 用户列表已审查 is_super 标志，普通用户已分配角色
  • 新建文章默认草稿，可提交审核/发布；版本历史可用
  • 上传 JPG 生成缩略图且压缩；伪静态、消息通知、备份按需配置验证

完整内容（手工 SQL、回滚方案、变更明细附录）见 UPGRADE.md。

十四、REST 内容 API（v2.2）

v2.2 新增只读内容 API，前缀 /api/v1，供小程序、App、Headless 前端（Nuxt/Next/Vue 等）直接消费。所有端点遵循统一响应包、鉴权规则、CORS、缓存策略，插件可向同一蓝本追加自己的只读端点。

1. 配置与鉴权

后台「系统设置 → 内容 API」可配置：

  • 内容 API 总开关（api_enable）：关闭后所有 /api/v1/* 返回 404，不暴露存在性。
  • 访问 Token（api_token）：非空时要求请求头 X-API-Token: {token}，缺失或错误返回 401。
  • CORS 允许来源（api_cors_origins）：* 或逗号分隔域名；* 下响应头 Access-Control-Allow-Origin: *，适合本地调试与公共开放站；生产如需更严，请逐个列域名（如 https://m.example.com,https://admin.example.com）。
  • 缓存 TTL（api_cache_ttl）：默认 300 秒；使用 Flask-Caching，按「端点类型 + 路径 + 查询」维度独立键，插件启停时不会串页。

改动以上任意一项均写入审计日志（模块=系统设置，操作=修改）。

2. 统一响应格式

{
  "code": 0,        // 0=成功，其他=业务错误码
  "message": "ok",  // 错误时为中文说明
  "data": ...,      // 成功时返回数据
  "meta": {         // 列表端点附带分页信息；否则 null
    "page": 1,
    "per_page": 10,
    "total": 128,
    "pages": 13
  }
}

错误示例：{"code":401,"message":"Token 无效或缺失","data":null,"meta":null}。

3. 核心端点

  • GET /api/v1/columns：栏目导航树（含 type/slug/外链 URL/list_template 等，仅启用+未删除+非外链栏目可下钻）。
  • GET /api/v1/columns/<slug>：栏目详情（封面图、SEO 三字段、父级/子级摘要等）。
  • GET /api/v1/columns/<slug>/articles?page=1&per_page=10&keyword=：栏目文章分页（仅发布+未删除），per_page 范围 1-50。
  • GET /api/v1/articles/<id>：文章详情（正文 HTML、SEO、自定义字段值、prev/next 指针）。

4. 插件扩展端点（v2.2）

  • GET /api/v1/banners/<slug>：轮播图插件。返回分组下按 sort_order 排序的启用项列表（含图片 URL、标题、链接、link_target）；插件未启用或分组不存在返回 404。
  • GET /api/v1/columns/<slug>/products + GET /api/v1/products/<id>：产品展示插件。列表支持分页+关键词；详情附带相册 URL 列表、分组规格参数、上一条/下一条产品指针；插件未启用或产品不存在/未启用返回 404。
第三方插件开发时请一律把端点挂在核心 api_bp（get_api_routes(api_bp) 钩子），这样会自动享受总开关、鉴权、CORS、缓存装饰器与审计，不要单独注册新的顶层蓝本。

十五、插件机制（v2.2）

v2.2 的核心底座是「插件优先架构」：所有非通用能力（轮播、产品、表单扩展、FAQ、招聘、下载中心、留言板…）都以插件形式开发，无需修改核心源码即可部署；启停只改一项 Setting 值，即时生效、无需重启、禁用即隐身。

1. 架构总览

  • 发现与加载：应用启动时调用 discover_and_load(app)，扫描 plugins/*/__init__.py 并导入；单个插件导入失败仅记录错误并在管理页标红，不拖垮启动。
  • 门控：运行时以 Setting('enabled_plugins') = 'banner,product,...' 逗号分隔 slug 集合为唯一真值。plugin_enabled(slug) 请求级 memo，按次查询。
  • 启用：幂等写入权限点 → 给预设角色（content_editor/content_auditor/super_admin 等）补授权 → db.create_all() 兜底建插件表 → 写启用清单。
  • 禁用：仅从启用清单移除 slug，不删表、不清数据、不回收权限绑定（核心零迁移；下次启用直接复用历史数据）。前台/后台门控：未启用的插件→路由 404、菜单不显示、sitemap 不收录、API 返回 404、模板函数返回 fallback。

2. 官方内置插件

slug名称适用场景资源路径 / 关键字
banner轮播图首页幻灯片、侧边广告位、横幅分组banner_items('home-hero')；banner/hero_carousel.html partial；GET /api/v1/banners/<slug>
product产品展示制造业/贸易产品库、相册 + 规格参数、区别普通文章product_latest('products', 8)；/product-<id>.html 伪静态；list_product.html 列表模板；GET /api/v1/products/<id>

3. 后台：插件管理页

入口：后台侧边栏「系统 → 插件管理」（权限点：system:plugins_manage）。页面列出所有已发现插件的元数据（名称/版本/作者/说明），导入错误的插件会以红色「加载失败」徽标标注错误栈；启用插件会弹出确认说明并写入审计日志（模块=系统设置，操作=修改，changed.enabled_plugins = [旧清单, 新清单]）。

4. 初始化向导集成

新装初始化向导在「演示数据选择」后新增「功能插件」勾选步骤，默认勾选 轮播图 + 产品展示：

  • 勾选 → 核心演示数据生成后立即调用 run_demo_data_hooks(industry)，生成 banner 分组 3 张图 / 制造业 6 产品；同时自动给 content_editor / content_auditor 绑定插件权限点。
  • 不勾选 → 启用清单为空、不建插件数据、栏目模板不被改动；后续需要时在「插件管理」一键启用即可。

十六、插件开发指引（v2.2）

本章节面向想开发自定义插件的开发者，从目录结构 → 元数据 → 钩子方法 → 测试清单，走完一个完整插件的开发流程。建议以 plugins/banner（最简后台+模板函数）和 plugins/product（完整 CRUD + 前台路由 + API）作为样板对照。

1. 目录结构约定

plugins/
  my_plugin/              # 插件根目录，slug 必须符合 [a-zA-Z0-9_-]{2,32}
    manifest.json         # 纯元数据（管理页展示 + min_core_version 校验）
    __init__.py           # 入口：定义 PluginBase 子类，末尾实例化为变量 `plugin`
    models.py             # SQLAlchemy 模型（导入即进入 metadata，启用时 db.create_all 建表）
    admin.py              # 后台路由（挂核心 admin_bp，endpoint 归入 admin.*）
    frontend.py           # 前台模板函数（jinja globals）+ URL 生成
    frontend_routes.py    # 前台蓝图路由（可选，仅当需要独立 URL）
    api.py                # REST API 端点（挂核心 api_bp，统一响应包）
    demo.py               # 演示数据钩子：generate(industry)，幂等
    templates/            # Jinja 模板目录：后台页 / 前台 partial / 前台详情页
      my_plugin/          # 建议 namespace，避免与核心模板重名
        index.html
        form.html
        show_detail.html
    static/               # 插件静态资源（可选；蓝图注册 static_url_path 暴露）
      css/my.css
      js/my.js

2. manifest.json（元数据）

{
  "slug": "my_plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "description": "一句话说明该插件做什么，会显示在插件管理页。",
  "author": "你的名字或团队",
  "min_core_version": "2.2.0"
}

min_core_version 用于未来核心 API 变更时提示升级；当前最低 2.2.0。

3. 入口：PluginBase 子类 + plugin = MyPlugin()

最简骨架（可直接复制粘贴再改类名）：

"""my_plugin 插件入口。"""
from app.plugin_api import PluginBase

from . import admin as _admin  # noqa: F401  导入即向 admin_bp 注册后台路由
from . import api as _api      # noqa: F401  可选：导入即准备好 API 注册器


class MyPlugin(PluginBase):
    # --- 元数据（与 manifest.json 保持一致，类属性优先） ---
    slug = 'my_plugin'
    name = '我的插件'
    version = '1.0.0'
    description = '示例插件：演示全部钩子的用法'
    author = '开发者名称'

    # --- 声明式注册 ---
    # 权限点：启用时幂等写入 permissions 表
    permissions = [
        ('my_plugin:manage', '我的插件管理', '增删改查管理权限'),
    ]
    # 启用时幂等给预设角色补授权（可留空）
    preset_role_grants = {
        'content_auditor': ['my_plugin:manage'],
        'content_editor':  ['my_plugin:manage'],
    }
    # 审计模块：筛选下拉 + 列表徽标翻译（可留空）
    audit_modules = [('my_plugin', '我的插件')]

    # --- 代码钩子（按需求覆写） ---

    def get_admin_menu(self):
        """侧边栏菜单项：启用 + 当前用户有权限才显示。"""
        return [{
            'label': '我的插件',
            'endpoint': 'admin.my_plugin_index',  # admin 蓝本 endpoint
            'icon': 'fa-cog',                      # FontAwesome 图标
            'permission': 'my_plugin:manage',
            'active_prefix': 'my_plugin',          # active_menu 高亮前缀
        }]

    def get_admin_menu_icon(self):
        """侧边栏整组图标，默认 fa-plug。"""
        return 'fa-cube'

    def get_admin_routes(self, admin_bp):
        """如需在 __init__.py 中集中注册路由，可覆写此方法。"""
        pass

    def get_frontend_blueprint(self):
        """返回前台蓝图；即使无前台路由也可返回仅含 template_folder 的蓝图，
        用于把插件模板目录接入 Jinja 搜索链。"""
        from flask import Blueprint
        return Blueprint('my_plugin_frontend', __name__,
                         template_folder='templates',
                         static_folder='static',
                         static_url_path='/plugins-static/my_plugin')

    def get_jinja_globals(self):
        """模板全局函数：核心自动包裹"插件启用"守卫；未启用时返回 fallback。"""
        from .frontend import my_plugin_items
        return {'my_plugin_items': my_plugin_items}

    def get_jinja_fallbacks(self):
        """同名函数禁用时的兜底返回值（避免模板 UndefinedError）。"""
        return {'my_plugin_items': []}

    def get_api_routes(self, api_bp):
        """向核心内容 API 蓝本注册只读端点。"""
        _api.register(api_bp)

    def get_sitemap_urls(self):
        """贡献 sitemap URL，返回 [{loc, lastmod, changefreq, priority}]；
        loc 为完整 URL，伪静态开启时优先用伪静态 URL。"""
        return []

    def generate_demo_data(self, industry):
        """演示数据钩子，industry='manufacturing' | 'service'。幂等！"""
        from .demo import generate
        generate(industry)


plugin = MyPlugin()   # 必须！核心通过 import 后取模块级 plugin 变量识别

4. 模型开发（models.py）

"""my_plugin 数据模型。
注意：只定义 db.Model 子类即可——import models 时即进入 metadata；
启用插件时 db.create_all() 会幂等建表；禁用插件后仍保留表与数据。
"""
from datetime import datetime
import json
from app.extensions import db

class MyItem(db.Model):
    __tablename__ = 'my_items'
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    is_enabled = db.Column(db.Boolean, default=True, nullable=False)
    is_deleted = db.Column(db.Boolean, default=False, nullable=False)
    sort_order = db.Column(db.Integer, default=0, nullable=False)
    created_at = db.Column(db.DateTime, default=datetime.now, nullable=False)
    updated_at = db.Column(db.DateTime, default=datetime.now,
                           onupdate=datetime.now, nullable=False)
表名建议带插件 slug 前缀（如 my_items），避免与核心或其他插件冲突；模型必须含 is_deleted 字段并在查询中显式过滤，遵循核心的"软删除、便于批量恢复"策略。

5. 后台管理路由（admin.py）

后台路由直接从核心 admin_bp 注册，endpoint 归入 admin.*，从而自动获得后台地址前缀即时生效机制（无需为你的插件单独处理前缀切换）。关键装饰器三件套：

from app.admin import admin_bp                       # 核心后台蓝本
from app.utils.helpers import permission_required, audit_log  # 权限 + 审计
from app.models.audit import OP_CREATE, OP_UPDATE, OP_DELETE
from .models import MyItem, AUDIT_MODULE = 'my_plugin'

@admin_bp.route('/my-items')                          # URL: /{admin_prefix}/my-items
@permission_required('my_plugin:manage',
                     any_of=['content:edit','content:delete'])  # any_of=聚合权限点
def my_plugin_index():
    items = MyItem.query.filter_by(is_deleted=False).all()
    return render_template('my_plugin/index.html', items=items)

@admin_bp.route('/my-items/<int:iid>/delete', methods=['POST'])
@permission_required('content:delete')
def my_plugin_delete(iid):
    item = MyItem.query.get_or_404(iid)
    item.is_deleted = True
    db.session.commit()
    audit_log(OP_DELETE, AUDIT_MODULE, item.id, item.title,
              detail={'remark': '软删除'})  # 改动作出审计
    flash('已删除', 'success')
    return redirect(url_for('admin.my_plugin_index'))

权限点策略参考官方插件：my_plugin:manage 是语义聚合权限（后台菜单用），而 CRUD 的细粒度仍沿用核心的 content:create/edit/delete/batch，这样「内容编辑」「内容审核」预设角色只要绑定一次 my_plugin:manage 就立即获得全套 CRUD 权限。

6. 前台模板函数与蓝图（frontend.py + frontend_routes.py）

模板函数不要直接写在蓝图函数中；应声明为纯函数，在 get_jinja_globals() 注册。核心会给它自动套「启用守卫」：未启用插件时返回 get_jinja_fallbacks() 中声明的默认值（[] / None），避免模板抛错。

# frontend.py（模板函数 + URL 生成）
from flask import url_for
from app.models.setting import Setting
from .models import MyItem

def frontend_item_url(item):
    """伪静态优先的详情 URL。"""
    if Setting.get('seo_rewrite_enable') == 'on':
        return f'/my-{item.id}.html'
    return url_for('my_plugin_frontend.item_detail', iid=item.id)

def my_plugin_items(limit=6):
    """前台调用：{{ my_plugin_items(4) }}。"""
    rows = MyItem.query.filter_by(is_enabled=True, is_deleted=False) \
        .order_by(MyItem.sort_order.desc(), MyItem.id.desc()).limit(limit).all()
    return [{'id': r.id, 'title': r.title, 'url': frontend_item_url(r)}
            for r in rows]
# frontend_routes.py（前台蓝图路由）
from flask import Blueprint, render_template, abort
from app.models.setting import Setting

                               template_folder='templates')

@my_plugin_frontend.route('/my-<int:iid>.html')
def item_detail_rewrite(iid):
    """伪静态路由（只有 seo_rewrite_enable=on 时返回 200）。"""
    if Setting.get('seo_rewrite_enable') != 'on':

7. REST API（api.py）

"""my_plugin：只读 API 端点。"""
from app.api.views import api_ok, api_err, api_cache
from app.plugin_system import plugin_enabled

def register(api_bp):
    @api_bp.route('/my-items')
    @api_cache('my_item')  # 独立缓存键维度：my_item
    def my_items_list():
        if not plugin_enabled('my_plugin'):
            return api_err(404, '资源不存在')   # 未启用/不存在统一 404
        from .models import MyItem
        rows = MyItem.query.filter_by(
            is_enabled=True, is_deleted=False
        ).order_by(MyItem.sort_order.desc()).limit(50).all()
        return api_ok([
            {'id': r.id, 'title': r.title} for r in rows
        ])

8. 自测清单（插件发布前必过）

  • 插件目录放入后，启动应用无异常；插件管理页显示"已加载"、版本/作者/说明与 manifest.json 一致。
  • 启用：权限点种子成功（数据库 permissions 表新增）、预设角色授权成功、模型表 SHOW TABLES / .tables 存在、侧边栏菜单在有 my_plugin:manage 权限的角色下显示。
  • 后台 CRUD：创建/编辑/删除/批量 → 审计日志有记录、模块筛选下拉含「我的插件」、?module=my_plugin 过滤命中。
  • 模板：前台调用模板函数 → 渲染；禁用插件 → 同一个模板不报错、返回 fallback 空值。
  • 前台路由：动态详情 200；伪静态开启时 /my-<id>.html 200，关闭时 404 且核心 /article-<id>.html、/{slug}-{N}.html 分页不被劫持。
  • API：api_enable=on 200，off 404；有 Token 时缺失/错误返回 401；CORS 头匹配配置；插件禁用后 API 返回 404。
  • sitemap：有详情页的插件 → sitemap.xml 含 <loc>；禁用插件 → sitemap 中消失。
  • 演示数据钩子：两次调用 generate（幂等）→ 记录数不变、无 IntegrityError；服务业/制造业分支覆盖。
  • 禁用：插件管理页禁用 → 前台路由/API/菜单/sitemap 全部隐身；重新启用 → 历史数据全部恢复可见，权限点/授权/建表动作不重复。
  • 升级兼容：在 v2.1.1 已运行实例上覆盖代码 → 无需重启即可看到插件管理页、启用后立即生效。

9. 常见陷阱与最佳实践

  • 后台路由 endpoint 命名：admin.my_plugin_{action}。不要自己注册新蓝本，否则后台前缀切换时你的插件路由不会即时失效。
  • 文件名判断上传类型时，用 secure_filename 之前的原始文件名取后缀（核心 save_upload_file 已处理，直接复用即可）。
  • 模板中使用字典时，g['items'] 不要写成 g.items——后者会命中 dict 的 items() 方法而非键值。
  • 新建数据库时，模型 import 必须发生在 db.create_all() 之前。核心在应用工厂最后才执行 create_all，因此你的 __init__.py 必须显式 from . import admin（admin.py 再导入 models.py），保证模型已被注册。
  • 插件 __init__.py 末尾一定要实例化为 plugin = MyPlugin()，否则 plugin_system 会判定加载失败（且没有友好提示）。
  • 伪静态产品 URL /product-{id}.html 优先级必须高于栏目分页规则 /{slug}-{N}.html；核心 frontend_routes.py 已确保此顺序，新增插件时若声明 /foo-{id}.html 格式，要在 README 注明并加入回归测试。
