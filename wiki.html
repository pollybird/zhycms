zhycms 使用手册

基于 Flask 的轻量级企业网站 CMS — 目录结构 · 安装初始化 · 部署 · 模板制作教程

项目简介

zhycms 是一个基于 Flask + SQLAlchemy 的轻量级内容管理系统，内置多主题模板引擎、栏目级模板选择、自定义字段、表单收集、SEO 优化等能力，适合搭建企业官网、资讯门户、产品展示站等。

特性一览

  • 多主题模板系统：前台模板按主题组织，后台一键切换。内置 default、blue 两套通用聚合主题，以及 manufacturing（制造业）、service（服务业）两套行业专用主题。
  • 演示数据一键生成：初始化时可选「制造业」或「服务业」示例，自动生成栏目、文章、碎片、友情链接与演示图片并切换主题。
  • CMS 标识与企业标识分离：后台 CMS 名称/版权固定不可改，前台网站名称/版权可独立配置。
  • 栏目级模板选择：每个栏目可指定独立的列表页/内容页/单页模板，未指定自动回退默认。
  • 自定义字段：栏目和文章支持自定义字段（文本/富文本/图片/文件/URL/数字等）。
  • 表单收集：可视化表单设计，支持文本/手机/邮箱/单选/多选/文件上传，带图形验证码防刷，提交数据可导出。
  • SEO 优化 / 碎片管理 / 友情链接 / 图片上传（压缩·水印） / 验证码登录 / 首次初始化引导。

一、目录结构

zhycms/
├── app/
│   ├── admin/              # 后台模块（栏目、文章、表单、设置等）
│   ├── frontend/           # 前台模块（路由与视图）
│   │   └── templates/
│   │       └── themes/     # ★ 前台主题模板目录
│   │           ├── default/        # 通用聚合主题
│   │           ├── blue/           # 通用聚合主题（蓝色）
│   │           ├── manufacturing/  # 制造业行业专用主题（产品置顶）
│   │           └── service/        # 服务业行业专用主题（公司介绍置顶）
│   ├── models/             # 数据模型
│   ├── utils/              # 工具模块（主题、上传、验证码、数据库配置等）
│   ├── static/             # 静态资源（uploads/ 上传文件、admin/ 后台资源）
│   ├── __init__.py         # 应用工厂 create_app
│   ├── config.py           # 配置（含数据库 URI 解析）
│   └── extensions.py       # 扩展初始化
├── instance/               # 实例数据（zhycms.db 数据库、db_config.json 连接配置）
├── requirements.txt        # 依赖清单（含 MySQL/PostgreSQL 驱动）
├── run.py                  # 启动入口
├── .gitignore
└── LICENSE                 # Apache 2.0
提示：instance/ 目录存放 SQLite 数据库与 db_config.json（含数据库连接信息，可能包含密码），已在 .gitignore 中排除，切勿提交到版本库。

二、安装与初始化

环境要求

  • Python 3.9+
  • SQLite（默认，开箱即用）或 MySQL / PostgreSQL

安装步骤

# 克隆代码
git clone <your-repo-url> zhycms
cd zhycms

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

# 安装依赖（国内建议使用镜像源加速）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
# 清华源： -i https://pypi.tuna.tsinghua.edu.cn/simple

# 启动开发服务器
python run.py
requirements.txt 已内置 MySQL 驱动 PyMySQL 与 PostgreSQL 驱动 psycopg2-binary，初始化时选择对应数据库类型即可，无需额外安装。

初始化向导

浏览器访问 http://127.0.0.1:5000，首次访问会自动跳转到 /admin/setup 初始化向导。向导中需要填写：

  • 管理员账号（至少 3 个字符）与密码（至少 6 个字符，需二次确认）
  • 数据库类型：SQLite / MySQL / PostgreSQL（见下）
  • 演示数据：不生成 / 制造业 / 服务业

提交后系统会创建管理员、写入默认设置，并按选择生成演示数据，随后跳转登录页。

数据库选择

类型说明需要填写
SQLite默认，直接生成 instance/zhycms.db 文件，零配置无
MySQL连接已有 MySQL 服务，默认端口 3306主机、端口、数据库名、用户名、密码
PostgreSQL连接已有 PostgreSQL 服务，默认端口 5432主机、端口、数据库名、用户名、密码
选择 MySQL/PostgreSQL 时，向导会先测试连接，成功后才将连接信息写入 instance/db_config.json 并热切换数据库引擎；若切换失败会自动回滚到原库，保证应用可继续运行。
数据库 URI 解析优先级（见 app/config.py）：
环境变量 ZHOCMS_DB_URI > instance/db_config.json（初始化向导所存） > 默认 SQLite。

三、部署

开发模式

python run.py
# 监听 0.0.0.0:5000，默认开启 DEBUG，代码/模板改动自动重载

生产部署

# 直接运行（关闭 DEBUG）
ZHOCMS_ENV=production ZHOCMS_SECRET_KEY=your-secret python run.py

# 或使用 gunicorn（推荐）
gunicorn -w 4 -b 0.0.0.0:5000 "run:app"
生产环境注意：务必通过 ZHOCMS_SECRET_KEY 设置自定义会话密钥；建议在 gunicorn 前置 Nginx 反向代理并托管 app/static/ 静态资源。

环境变量

变量默认值说明
ZHOCMS_ENVdevelopment配置模式：development / production
ZHOCMS_SECRET_KEY内置默认值会话加密密钥，生产环境必须修改
ZHOCMS_DB_URIsqlite:///instance/zhycms.db数据库 URI，可换成 MySQL/PostgreSQL；优先级最高

四、CMS 标识与网站标识

系统严格区分「CMS 自身标识」与「前台企业标识」四个概念，避免演示数据或用户配置误改后台品牌：

概念显示位置取值来源可否修改
CMS 名称后台顶栏 / 登录页 / 后台标题Setting.CMS_NAME 固定常量❌ 不可改
后台版权后台底部Setting.CMS_COPYRIGHT 固定常量❌ 不可改
网站名称前台导航 / 首页 / 页脚Setting 'site_name'（企业名）✅ 网站设置可改
前台版权前台底部Setting 'footer_copyright'✅ 网站设置可改
约定：后台模板一律使用 cms_name / cms_copyright（由 app/__init__.py 的上下文处理器注入），不得读取 site_settings.site_name / site_settings.footer_copyright（那是前台企业信息）；前台模板则相反。

五、演示数据与行业主题

选项生成内容自动切换主题
不生成仅创建管理员，空站点保持 default
制造业精密机械制造企业示例：关于我们、产品中心、新闻中心、联系我们等栏目 + 文章 + 碎片 + 友情链接 + 演示图片manufacturing（产品置顶）
服务业企业管理咨询公司示例：关于我们、服务项目、行业动态、客户案例、联系我们等栏目 + 文章 + 碎片 + 友情链接 + 演示图片service（公司介绍置顶）
  • 演示数据由 app/utils/bootstrap.py 的 generate_demo_data(industry) 生成。
  • 每次生成会先调用 _clean_demo_data() 按外键依赖顺序清理旧数据（表单 → 文章 → 栏目 → 碎片 → 友情链接），因此可在两个行业间反复切换而不会触发 slug 唯一约束冲突。
  • 演示图片位于 app/static/uploads/demo/（制造业 mfg_*、服务业 svc_*），无需联网即可展示。
  • 演示数据只写入前台企业信息，不会改动后台 CMS 名称与版权。

六、模板制作教程

zhycms 前台采用 多主题 + 栏目级模板 的双层机制，主题可在网站设置一键切换，栏目可单独指定列表/内容/单页模板。模板基于 Jinja2 + Bootstrap 4。

1. 主题目录结构

所有主题存放在 app/frontend/templates/themes/ 下，每个主题是一个独立目录，目录名即主题名：

themes/default/
├── base.html            # 基础布局（必须）
├── index.html           # 首页（必须）
├── list.html            # 列表页默认模板（必须）
├── article.html         # 文章详情默认模板（必须）
├── page.html            # 单页默认模板（必须）
├── list_card.html       # 卡片式列表（可选，栏目备选模板）
├── column_children.html # 父栏目展示子栏目列表
├── search.html          # 搜索结果页
├── form.html            # 表单提交页（含验证码）
├── form_closed.html     # 表单关闭提示页
├── closed.html          # 站点关闭提示页
├── 404.html
└── 500.html

必备模板

文件用途
base.html全站基础骨架，所有页面通过 {% extends theme_base %} 继承
index.html站点首页
list.html列表栏目默认列表页（名称固定 list）
article.html文章详情默认页（名称固定 article）
page.html单页栏目默认页（名称固定 page）
404.html / 500.html错误页
closed.html站点关闭时展示

可选模板（栏目级备选）

凡以 list、article、page 开头的 .html 文件，会自动出现在后台栏目编辑页的下拉选项中：

  • list_xxx.html → 列表栏目可选用
  • article_xxx.html → 文章详情页可选用
  • page_xxx.html → 单页栏目可选用
受保护模板（即使以上述前缀开头也不会列为栏目备选，因为它们是系统级模板）：
base、404、500、closed、form_closed、index、search、column_children、form

2. 创建一个新主题

以创建名为 green 的绿色风格主题为例：

步骤 1：复制默认主题作为起点

cp -r app/frontend/templates/themes/default app/frontend/templates/themes/green

步骤 2：修改 base.html 中的样式

/* 主题色：绿色 */
.navbar { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%) !important; }
.footer { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%); color:#e8f5e9; }
.card-header { background:#2e7d32; color:#fff; }
.btn-primary { background-color:#2e7d32; border-color:#2e7d32; }
a { color:#2e7d32; } a:hover { color:#1b5e20; }

步骤 3：在后台启用

进入 后台 → 网站设置 → 前台主题，下拉框会自动出现 green 选项，选中保存即可。

主题的发现是自动的：扫描 themes/ 下所有子目录，无需在代码中注册。

3. 模板继承与 theme_base

所有页面模板通过 {% extends theme_base %} 继承当前主题的 base.html，而不是写死路径：

{% extends theme_base %}
{% block title %}页面标题{% endblock %}
{% block content %}
  页面内容
{% endblock %}

theme_base 由上下文处理器注入，值类似 themes/default/base.html，切换主题时自动找到对应的 base.html。

base.html 必须提供的 block

Block 名用途
title<title> 标签内容
css页面级 CSS（在 <head> 内）
content主体内容
js页面级 JS（在 </body> 前）

4. 全局模板变量

以下变量在所有前台模板中可直接使用（由 app/__init__.py 的 context_processor 注入）：

变量类型说明
site_settingsdict站点设置，含前台企业标识：site_name、site_subtitle、site_logo、footer_copyright 等
site_fragmentsdict碎片内容，键为碎片 slug，值为 Fragment 对象（访问 .value）
nav_columnslist顶层栏目列表
current_themestr当前主题名（如 default）
theme_basestr当前主题 base 模板路径
cms_name / cms_copyrightstrCMS 名称 / 后台版权（固定），仅后台使用

视图函数传入的常用变量

  • 首页 index.html：nav、first_page、latest_articles、friend_links、seo；行业主题另有 about_col、products_col/products、services_col/services、news_col/news、cases_col/cases（按 slug 约定收集，通用主题忽略）
  • 列表页 list.html：column、articles、pagination、nav、seo
  • 文章详情 article.html：column、article、fields、latest_articles、prev_article、next_article、nav、seo
  • 单页 page.html：column、nav、seo
  • 表单 form.html：form、fields、nav、seo
  • 搜索 search.html：keyword、results、nav、seo
  • 父栏目 column_children.html：column、children、nav、seo

Article（文章）

{{ article.title }}
{{ article.summary }}

Pagination（分页）

{{ pagination.page }}  {{ pagination.pages }}
{{ pagination.has_prev }}  {{ pagination.has_next }}
{{ pagination.prev_num }}  {{ pagination.next_num }}

{% endif %}

6. URL 生成与自定义过滤器

{{ url_for('frontend.index') }}                                   {# 首页 #}
{{ url_for('frontend.column_detail', slug=column.slug) }}         {# 栏目页 #}
{{ url_for('frontend.column_detail', slug=column.slug, page=2) }} {# 带分页 #}
{{ url_for('frontend.article_detail', slug=column.slug, aid=article.id) }} {# 文章 #}
{{ url_for('frontend.form_submit', slug=form.slug) }}             {# 表单 #}
{{ url_for('frontend.search') }}                                  {# 搜索 #}
过滤器用途示例
date格式化日期{{ article.published_at|date }} → 2026-08-06
datetime格式化日期时间{{ article.published_at|datetime }} → 2026-08-06 22:30
truncate_text截断文本{{ article.summary|truncate_text(80) }}

7. 制作栏目级备选模板

以制作「卡片式列表模板」为例。步骤 1：在主题目录下创建以 list 开头的文件 list_card.html。步骤 2：编写模板内容（继承 theme_base，遍历 articles 渲染卡片，用 pagination 生成分页）。步骤 3：进入后台栏目编辑页，「列表页模板」下拉框会出现 list_card 选项，选中保存即可。

前缀对应栏目模板类型出现位置
list_*列表页模板列表栏目的「列表页模板」下拉
article_*内容页模板列表栏目的「内容页模板」下拉
page_*单页模板单页栏目的「单页模板」下拉
若栏目指定的模板在当前主题中不存在（如切换主题后新主题没有该模板），系统会自动回退到默认模板（list / article / page），不会报错。

自定义字段渲染示例（文章详情页片段）

{% for f in fields %}
  {% set val = article.get_field_value(f.id) %}
  {% if val %}
  <tr><th>{{ f.label }}</th><td>
    {% if f.field_type == 'image' %}<img src="{{ val }}">
    {% elif f.field_type == 'file' %}<a href="{{ val }}">下载</a>
    {% elif f.field_type == 'url' %}<a href="{{ val }}" target="_blank">{{ val }}</a>
    {% elif f.field_type == 'richtext' %}{{ val|safe }}
    {% else %}{{ val }}{% endif %}
  </td></tr>
  {% endif %}
{% endfor %}

8. 模板制作检查清单

  • 目录 app/frontend/templates/themes/<主题名>/ 已创建
  • 包含必备文件：base / index / list / article / page / 404 / 500 / closed
  • 所有页面通过 {% extends theme_base %} 继承（不硬编码主题路径）
  • base.html 提供 title / css / content / js 四个 block
  • 富文本内容使用 |safe 过滤器
  • 列表页、文章页的分页链接正确使用 pagination 对象
  • 后台「网站设置 → 前台主题」下拉框能看到新主题
  • 切换到新主题后，首页、栏目页、文章页、单页、404 均能正常访问
  • 自定义字段按 field_type 区分图片/文件/URL/富文本正确渲染

9. 调试技巧

  • 调试模式：python run.py 默认开启 DEBUG，模板修改自动重载。
  • 查看当前主题：在任意模板中输出 {{ current_theme }}。
  • 查看可用模板：Python Shell 中执行 list_themes() / list_theme_templates(category='list')（见 app/utils/themes.py）。
  • 模板找不到报错：检查文件名是否准确（区分大小写），是否放在正确的主题目录下。
