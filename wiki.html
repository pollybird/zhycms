项目简介

zhycms 是一个基于 Flask + SQLAlchemy 的轻量级内容管理系统，内置多主题模板引擎、栏目级模板选择、自定义字段、表单收集、SEO 优化等能力，适合搭建企业官网、资讯门户、产品展示站等。

v2.0 围绕「企业级安全、可控、可运维」新增八大模块：RBAC 权限体系、审计日志、内容工作流、备份恢复、登录安全加固、上传安全与图片优化、表单消息通知、SEO 与站点性能。

从 v1.1 升级：v2.0 新增 9 张数据表、旧表补 12 列与 4 个依赖，请先阅读项目根目录的 UPGRADE.md 升级迁移指南，并执行幂等迁移脚本 scripts/upgrade_v2.py 完成数据库迁移（仅启动程序无法完成迁移，且可能把原本隐藏的文章错误公开）。

特性一览

  • 多主题模板系统：前台模板按主题组织，后台一键切换。内置 default、blue 两套通用聚合主题，以及 manufacturing（制造业）、service（服务业）两套行业专用主题。
  • 演示数据一键生成：初始化时可选「制造业」或「服务业」示例，自动生成栏目、文章、碎片与演示图片并切换主题；勾选的官方插件还会通过演示数据钩子生成轮播图、产品、友情链接、表单示例数据。
  • CMS 标识与企业标识分离：后台 CMS 名称/版权固定不可改，前台网站名称/版权可独立配置。
  • 栏目级模板选择：每个栏目可指定独立的列表页/内容页/单页模板，未指定自动回退默认。
  • 自定义字段：栏目和文章支持自定义字段（文本/富文本/图片/文件/URL/数字等）。
  • 表单收集：可视化表单设计，支持文本/手机/邮箱/单选/多选/文件上传，带图形验证码防刷，提交数据可导出；v2.0 支持提交后邮件/企业微信实时通知；v2.3 起由核心功能转为官方内置插件（表名/路由/设置键不变，老站数据无缝保留）。
  • SEO 优化 / 碎片管理 / 图片上传 / 验证码登录 / 首次初始化引导。
  • v2.0 企业级能力：RBAC 角色权限、审计日志、内容工作流与版本还原、数据库备份恢复、登录防暴破、上传内容安全校验、伪静态与页面缓存。
  • v2.2 插件优先架构：轮播图、产品展示、友情链接均以官方内置插件提供，可随时启停；friend_links() 模板函数一行调用。
  • v2.3 国际化与统计插件：Flask-Babel 中英文自由切换（默认关闭）；官方内置统计代码插件（百度统计/GA4/站长工具/自定义代码，analytics_head()/analytics_body() 自动注入）；自定义表单转为官方内置插件。

二、安装与初始化

环境要求

  • Python 3.9+
  • SQLite（默认，开箱即用）或 MySQL / PostgreSQL

安装步骤

# 克隆代码
git clone <your-repo-url> zhycms
cd zhycms

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

# 安装依赖（国内建议使用镜像源加速）
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
# 清华源： -i https://pypi.tuna.tsinghua.edu.cn/simple

# 启动开发服务器
python run.py
requirements.txt 已内置 MySQL 驱动 PyMySQL 与 PostgreSQL 驱动 psycopg2-binary，初始化时选择对应数据库类型即可，无需额外安装。

初始化向导

浏览器访问 http://127.0.0.1:5000，首次访问会自动跳转到 /admin/setup 初始化向导。向导中需要填写：

  • 管理员账号（至少 3 个字符）与密码（至少 6 个字符，需二次确认）
  • 数据库类型：MySQL / PostgreSQL（生产推荐）/ SQLite（仅开发/测试，见下）
  • 演示数据：不生成 / 制造业 / 服务业

提交后系统会创建管理员、写入默认设置，并按选择生成演示数据，随后跳转登录页。

数据库选择

生产环境请选择 MySQL 5.7+ 或 PostgreSQL 12+：SQLite 不支持并发写入，正式站点使用容易锁表，仅适用于开发与测试。
类型说明需要填写
MySQL （生产推荐）生产首选（5.7+），连接已有 MySQL 服务，默认端口 3306主机、端口、数据库名、用户名、密码
PostgreSQL （生产推荐）生产可选（12+），连接已有 PostgreSQL 服务，默认端口 5432主机、端口、数据库名、用户名、密码
SQLite（仅开发/测试）默认选项，直接生成 instance/zhycms.db 文件，零配置；不支持并发写入，不要用于生产环境无
选择 MySQL/PostgreSQL 时，向导会先测试连接，成功后才将连接信息写入 instance/db_config.json 并热切换数据库引擎；若切换失败会自动回滚到原库，保证应用可继续运行。
数据库 URI 解析优先级（见 app/config.py）：
环境变量 ZHYCMS_DB_URI > instance/db_config.json（初始化向导所存） > 默认 SQLite。

三、部署

开发模式

python run.py
# 监听 0.0.0.0:5000，默认开启 DEBUG，代码/模板改动自动重载

生产部署

# 直接运行（关闭 DEBUG）
ZHYCMS_ENV=production ZHYCMS_SECRET_KEY=your-secret python run.py

# 或使用 gunicorn（推荐）
gunicorn -w 4 -b 0.0.0.0:5000 "run:app"
生产环境注意：务必通过 ZHYCMS_SECRET_KEY 设置自定义会话密钥；建议在 gunicorn 前置 Nginx 反向代理并托管 app/static/ 静态资源。

变量默认值说明

ZHYCMS_DB_URIsqlite:///instance/zhycms.db数据库 URI，可换成 MySQL/PostgreSQL；优先级最高

四、CMS 标识与网站标识

系统严格区分「CMS 自身标识」与「前台企业标识」四个概念，避免演示数据或用户配置误改后台品牌：

概念显示位置取值来源可否修改
CMS 名称后台顶栏 / 登录页 / 后台标题Setting.CMS_NAME 固定常量❌ 不可改
后台版权后台底部Setting.CMS_COPYRIGHT 固定常量❌ 不可改
网站名称前台导航 / 首页 / 页脚Setting 'site_name'（企业名）✅ 网站设置可改
前台版权前台底部Setting 'footer_copyright'✅ 网站设置可改
约定：后台模板一律使用 cms_name / cms_copyright（由 app/__init__.py 的上下文处理器注入），不得读取 site_settings.site_name / site_settings.footer_copyright（那是前台企业信息）；前台模板则相反。

六、模板制作教程

zhycms 前台采用 多主题 + 栏目级模板 的双层机制，主题可在网站设置一键切换，栏目可单独指定列表/内容/单页模板。模板基于 Jinja2 + Bootstrap 4。

1. 主题目录结构

所有主题存放在 app/frontend/templates/themes/ 下，每个主题是一个独立目录，目录名即主题 slug：

themes/default/
├── manifest.json      # 主题元数据（v2.2）：name/slug/version/description/author，
─                       #   builtin:true 标记官方内置，template_required 声明额外必备模板
├── base.html            # 基础布局（必须）
├── index.html           # 首页（必须）
├── list.html            # 列表页默认模板（必须）
├── article.html         # 文章详情默认模板（必须）
├── page.html            # 单页默认模板（必须）
├── list_card.html       # 卡片式列表（可选，栏目备选模板）
├── list_product.html    # 产品列表（可选，产品插件启用时可选用）
├── column_children.html # 父栏目展示子栏目列表
├── search.html          # 搜索结果页
├── form.html            # 表单提交页（含验证码）
├── form_closed.html     # 表单关闭提示页
├── closed.html          # 站点关闭提示页
├── 404.html
├── 500.html
├── css/                 # 主题样式目录（v2.2 起样式外置于此）
─   └── style.css       #   base.html 通过 theme_asset 引用
├── js/                  # 主题脚本目录（可选）
├── images/              # 主题静态图片目录（可选：背景图、图标、示例图等）
└── fonts/                # 主题字体文件目录（可选：woff/woff2/ttf 等）

主题静态资源引用（v2.2）

主题内 css/、js/、images/、fonts/ 四个目录下的文件通过前台资源路由自动对外服务，模板中用全局变量 current_theme 引用（跟随启用主题自动变化）：

<link rel="stylesheet" href="{{ url_for('frontend.theme_asset', slug=current_theme, filename='css/style.css') }}">
<script src="{{ url_for('frontend.theme_asset', slug=current_theme, filename='js/main.js') }}"></script>
<img src="{{ url_for('frontend.theme_asset', slug=current_theme, filename='images/hero.png') }}" alt="">
资源路由仅放行 css/、js/、images/、fonts/ 四个子目录并拦截路径穿越；manifest.json 与模板文件不对外暴露。全部资源随主题目录分发，主题打包下载时一并带走。

必备模板

文件用途
base.html全站基础骨架，所有页面通过 {% extends theme_base %} 继承
index.html站点首页
list.html列表栏目默认列表页（名称固定 list）
article.html文章详情默认页（名称固定 article）
page.html单页栏目默认页（名称固定 page）

可选模板（栏目级备选）

凡以 list、article、page 开头的 .html 文件，会自动出现在后台栏目编辑页的下拉选项中：

  • list_xxx.html → 列表栏目可选用
  • article_xxx.html → 文章详情页可选用
  • page_xxx.html → 单页栏目可选用
受保护模板（即使以上述前缀开头也不会列为栏目备选，因为它们是系统级模板）：
base、404、500、closed、form_closed、index、search、column_children、form

2. 创建一个新主题

以创建名为 green 的绿色风格主题为例：

步骤 1：复制默认主题作为起点

cp -r app/frontend/templates/themes/default app/frontend/templates/themes/green

步骤 2：修改主题样式

v2.2 起主题样式外置在 css/style.css 中（不再写进 base.html 的 <style> 标签），直接修改即可：

/* 主题色：绿色 */
.navbar { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%) !important; }
.footer { background: linear-gradient(135deg,#2e7d32 0%,#1b5e20 100%); color:#e8f5e9; }
.card-header { background:#2e7d32; color:#fff; }
.btn-primary { background-color:#2e7d32; border-color:#2e7d32; }
a { color:#2e7d32; } a:hover { color:#1b5e20; }

同时修改 manifest.json 中的 name / slug（slug 需符合 [a-zA-Z0-9_-]{2,32} 且与目录名一致）/ version / description。

步骤 3：在后台启用

进入 后台 → 系统设置 → 主题管理（v2.2 起主题启用入口已从「网站设置」迁移至此），列表中出现 green 后点击「启用」即可，前台即时生效。

主题的发现是自动的：扫描 themes/ 下所有子目录，无需在代码中注册。也可以把主题目录打包为 zip 后通过「主题管理」上传安装。

3. 模板继承与 theme_base

所有页面模板通过 {% extends theme_base %} 继承当前主题的 base.html，而不是写死路径：

{% extends theme_base %}
{% block title %}页面标题{% endblock %}
{% block content %}
  页面内容
{% endblock %}

theme_base 由上下文处理器注入，值类似 themes/default/base.html，切换主题时自动找到对应的 base.html。

base.html 必须提供的 block

Block 名用途
title<title> 标签内容
css页面级 CSS（在 <head> 内）
content主体内容
js页面级 JS（在 </body> 前）

七、用户、角色与权限（RBAC）

后台菜单 用户权限 → 用户列表 / 角色与权限（v2.0 新增）。

权限模型

  • 权限点两级授权：角色可勾选一组权限点，同时控制后台菜单可见性与操作按钮/接口（如文章发布、备份恢复、配置修改、用户管理）。
  • 多角色并集：一个用户可绑定多个角色，最终权限为所有角色权限点的并集。
  • 内容粒度授权：支持按栏目授予文章管理权限（如「只管理新闻中心」），实现内容运营岗位的最小权限分配。
  • 超级管理员：内置超管不受任何权限限制，普通用户未授权的菜单不可见、直接访问接口返回 403 并记录审计日志。
角色删除前会先解除用户绑定；用户被禁用后立即无法登录，已有会话在下一次请求时失效。

八、内容工作流与版本管理

文章编辑流程从 v1.1 的「直接发布」升级为可审核的工作流（v2.0 新增）：

状态流转

草稿(draft) ──提交审核──> 待审核(pending) ──审核通过──> 已发布(published)
    ▲                          │
    └────────驳回──────────────┘ 已驳回(rejected，需填写驳回原因)
  • 无发布权限的作者只能保存草稿并提交审核；有发布权限的编辑可直接发布。
  • 待审核文章只有具备审核权限的用户可见可操作，前台不展示。
  • 驳回时必须填写原因，作者可在文章列表看到驳回原因并修改后重新提交。

版本快照

  • 文章每次保存自动生成版本快照，记录标题/正文/摘要等完整内容与操作时间。
  • 文章编辑页 版本历史 中可查看任意两个版本的差异，支持一键还原到指定版本（还原动作本身也会生成新版本，可安全撤销）。

九、备份与恢复

后台菜单 备份运维 → 备份列表（v2.0 新增），备份文件存放于 instance/backups/。

备份方式

方式适用说明
MySQL 逻辑备份MySQL / MariaDB调用 mysqldump 导出全库结构与数据，gzip 压缩为 .sql.gz
PostgreSQL 备份PostgreSQL调用 pg_dump，同样 gzip 压缩
JSON 备份任意数据库与数据库类型无关的通用格式，适合小站点迁移或跨库切换

操作说明

  • 立即备份：选择备份方式一键执行，完成后列表显示文件名、大小、耗时与操作人。
  • 下载：将备份文件下载到本地异地保存。
  • 恢复：从备份文件一键恢复。恢复前系统自动提交并释放数据库连接池，避免 DROP TABLE 时被自身连接的元数据锁阻塞。
  • 删除：清理过期备份文件与记录。
恢复前务必确认：恢复操作会用备份内容覆盖当前数据库全部数据，且要求运行环境具备 mysqldump / pg_dump 命令（JSON 方式除外）。建议先下载一份当前备份再执行恢复。

十一、SEO 与站点性能

后台菜单 系统设置 → SEO 高级（v2.0 新增）。

伪静态 URL

开启伪静态后，前台自动支持以下 URL（关闭后这些地址返回 404，动态 URL 照常可用）：

URL含义等价动态 URL
/about.html栏目页（第一页）/column/about
/about-2.html栏目列表页第 2 页/column/about?page=2
/article-12.html文章详情/column/{slug}/article/12
  • 页面中的栏目、文章、分页链接会同步输出为伪静态格式（第 1 页输出 /about.html，不带 -1 后缀；第 N 页输出 /about-N.html）。
  • 访问 /about-1.html 会 301/302 规范化到 /about.html，避免搜索引擎收录重复页面。
  • 含连字符数字的栏目 slug（如 news-2024）可正确解析，不会被误切分为栏目 + 页码。
  • 开关即时生效，无需重启；自定义模板请使用全局助手 frontend_pager_url(column, page) 生成分页链接（见模板教程第 6 节）。

sitemap 与 robots

  • sitemap.xml：自动收录全部栏目与文章，栏目页/文章页的更新频率（changefreq）与优先级（priority）独立配置；伪静态开启时输出 .html 地址。
  • robots.txt：内置默认规则（跟随后台前缀 Disallow、屏蔽 /form/ 表单地址、声明 Sitemap），支持追加自定义规则；后台前缀变更后默认规则自动跟随。

页面缓存与图片 ALT

  • 页面缓存：基于 Flask-Caching，首页 / 栏目列表页 / 文章详情页可分别设置 TTL（默认 3600 / 1800 / 7200 秒）；发布、编辑、删除内容后自动清理对应缓存，不会出现「改了前台不更新」。
  • 图片默认 ALT：设置默认值后，前台渲染时自动为缺失或空 alt 的 <img> 填充（已设置 alt 的保留原值），提升无障碍访问与图片 SEO。
  • 图片ALT批量管理（系统设置 → 图片ALT批量管理）：后台工具页，批量排查全站文章/单页正文中的图片 ALT 缺失情况。

十二、安全加固

登录防暴破（v2.0）

  • 连续输错密码达到阈值（默认 5 次）自动锁定账号，锁定期内即使密码正确也会被拒绝；锁定时长默认 10 分钟，到期自动解锁。次数与时长均可在 系统设置 → 后台安全 中调整。
  • 登录页配备图形验证码；验证码错误会记录失败日志但不累计密码失败次数（验证码先于密码验证）。
  • 异地登录提醒：检测到与上次登录不同的 IP 城市时，登录成功后顶部展示一次性安全提醒横幅（可在设置中关闭）。
  • 所有登录行为（成功/失败/锁定）均写入 登录日志（系统设置 → 登录日志）。

后台路由前缀即时生效（v2.0）

系统设置 → 后台安全 中修改后台前缀（如 admin → manage-x8y2）后，v2.0 起即时生效、无需重启服务：新前缀立即可访问，旧前缀立即失效（404），后台页内跳转自动使用新前缀。历史前缀保存在 instance/admin_config.json，忘记路由时删除该文件可恢复默认 admin。

上传安全与图片优化（v2.0）

后台菜单 系统设置 → 上传安全，以下能力默认开启：

  • 后缀 + MIME 双重校验：除了校验后缀白名单，还检查文件真实内容（magic bytes）；伪装成 .jpg 的 PHP/Shell/可执行文件（含 <?php、#!、MZ、ELF 等特征）直接拒绝；图片后缀强制要求内容为真实图片。
  • SHA-256 内容去重：相同内容的文件全局只保存一份，多处引用自动计数（删除引用计数归零才真正清理磁盘）。
  • 图片自动压缩 + 缩略图：JPG/PNG 上传后自动压缩（质量默认 80，可调）并生成 300px 宽缩略图（可调），显著降低磁盘与流量开销。
  • 单文件大小上限默认 10MB，可配置；超限直接拒绝并给出明确提示。
  • 所有上传文件建立统一索引（原始大小/压缩后大小/宽高/缩略图路径/引用计数），可在后台查看与管理。

审计日志（v2.0）

后台菜单 审计日志：登录/登出、配置变更、内容增删改与发布审核、备份恢复、用户与权限调整等关键操作全量留痕，记录操作人、IP、操作时间、操作类型与详情；支持按模块、操作类型、操作人与时间范围检索，为安全追溯提供依据。

后台「系统设置 → 内容 API」可配置：

  • 内容 API 总开关（api_enable）：关闭后所有 /api/v1/* 返回 404，不暴露存在性。
  • 访问 Token（api_token）：非空时要求请求头 X-API-Token: {token}，缺失或错误返回 401。
  • CORS 允许来源（api_cors_origins）：* 或逗号分隔域名；* 下响应头 Access-Control-Allow-Origin: *，适合本地调试与公共开放站；生产如需更严，请逐个列域名（如 https://m.example.com,https://admin.example.com）。
  • 缓存 TTL（api_cache_ttl）：默认 300 秒；使用 Flask-Caching，按「端点类型 + 路径 + 查询」维度独立键，插件启停时不会串页。

改动以上任意一项均写入审计日志（模块=系统设置，操作=修改）。

十五、插件机制（v2.2 / v2.3）

v2.2 的核心底座是「插件优先架构」：所有非通用能力（轮播、产品、表单扩展、FAQ、招聘、下载中心、留言板…）都以插件形式开发，无需修改核心源码即可部署；启停只改一项 Setting 值，即时生效、无需重启、禁用即隐身。

1. 架构总览

  • 发现与加载：应用启动时调用 discover_and_load(app)，扫描 plugins/*/__init__.py 并导入；单个插件导入失败仅记录错误并在管理页标红，不拖垮启动。
  • 门控：运行时以 Setting('enabled_plugins') = 'banner,product,...' 逗号分隔 slug 集合为唯一真值。plugin_enabled(slug) 请求级 memo，按次查询。
  • 启用：幂等写入权限点 → 给预设角色（content_editor/content_auditor/super_admin 等）补授权 → db.create_all() 兜底建插件表 → 写启用清单。
  • 禁用：仅从启用清单移除 slug，不删表、不清数据、不回收权限绑定（核心零迁移；下次启用直接复用历史数据）。前台/后台门控：未启用的插件→路由 404、菜单不显示、sitemap 不收录、API 返回 404、模板函数返回 fallback。

4. 数据模型（models.py）：两张表与截止时间语义

招聘插件有两个模型：RecruitJob（岗位，主数据）与 RecruitApplication（求职申请，流水数据，外键关联岗位）。核心片段：

from datetime import datetime
from app.extensions import db


class RecruitJob(db.Model):
    """招聘岗位。"""
    __tablename__ = 'recruit_jobs'

    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    department = db.Column(db.String(100))            # 所属部门（可选）
    location = db.Column(db.String(200))              # 工作地点（可选）
    headcount = db.Column(db.Integer, default=1)      # 招聘人数（可选）
    salary = db.Column(db.String(100))                # 薪资待遇（可选）
    description = db.Column(db.Text)                  # 岗位介绍（富文本）
    deadline = db.Column(db.DateTime, index=True)     # 招聘截止时间（空=长期有效）
    is_enabled = db.Column(db.Boolean, default=True, nullable=False)
    is_deleted = db.Column(db.Boolean, default=False, nullable=False)
    sort_order = db.Column(db.Integer, default=0, nullable=False)
    created_by = db.Column(db.Integer, db.ForeignKey('users.id'))
    created_at = db.Column(db.DateTime, default=datetime.now, nullable=False)
    updated_at = db.Column(db.DateTime, default=datetime.now,
                           onupdate=datetime.now, nullable=False)

    # ---- 截止状态（业务语义收口在模型层，前后台共用） ----

    def is_expired(self):
        """是否已过招聘截止时间（未设截止时间视为长期有效）。"""
        if self.deadline is None:
            return False
        return datetime.now() > self.deadline

    def is_open(self):
        """是否开放申请：启用 + 未删除 + 未截止。"""
        return self.is_enabled and not self.is_deleted and not self.is_expired()

    def applications_count(self):
        return RecruitApplication.query.filter_by(job_id=self.id).count()


class RecruitApplication(db.Model):
    """求职申请。"""
    __tablename__ = 'recruit_applications'

    STATUS_PENDING = 'pending'    # 未处理
    STATUS_VIEWED = 'viewed'      # 已查看
    STATUS_PASS = 'pass'          # 录用
    STATUS_REJECT = 'reject'      # 不合适
    STATUS_LABELS = {STATUS_PENDING: '未处理', STATUS_VIEWED: '已查看',
                     STATUS_PASS: '录用', STATUS_REJECT: '不合适'}

    id = db.Column(db.Integer, primary_key=True)
    job_id = db.Column(db.Integer, db.ForeignKey('recruit_jobs.id'),
                       nullable=False, index=True)
    name = db.Column(db.String(64), nullable=False)     # 姓名
    phone = db.Column(db.String(32), nullable=False)    # 联系电话
    email = db.Column(db.String(128))
    education = db.Column(db.String(64))
    intro = db.Column(db.Text)

模型设计要点：

  • 表名带插件前缀（recruit_jobs / recruit_applications），避免与核心或其他插件冲突。
  • 软删除：主数据模型带 is_deleted 并在所有查询中显式过滤；流水数据（申请）直接硬删。
  • 业务语义收口在模型：is_open() / is_expired() 把"截止时间"规则写一次、前后台共用，避免视图里散落时间比较。
  • 可空字段表达可选语义：deadline 为空 = 长期有效，用 None 而非魔法值。
  • 只定义 db.Model 子类即可——import 时进入 metadata，启用插件时核心 db.create_all() 幂等建表；禁用不删表、不丢数据。

def _parse_deadline(raw):
    """解析 datetime-local 输入；空返回 None（长期有效），非法抛 ValueError。"""
    raw = (raw or '').strip()
    if not raw:
        return None
    for fmt in ('%Y-%m-%dT%H:%M', '%Y-%m-%d %H:%M:%S', '%Y-%m-%d %H:%M'):
        try:
            return datetime.strptime(raw, fmt)
        except ValueError:
            continue
    raise ValueError(raw)

def recruit_jobs(limit=10, only_open=False):

    if joined and os.path.isfile(joined):
        return joined
    return None

实现 get_sitemap_urls() 让岗位页被 /sitemap.xml 收录（伪静态开启时输出 /job-<id>.html 地址）：

def get_sitemap_urls(self):
    from flask import has_request_context, request
    from app.models.setting import Setting
    from .models import RecruitJob
    from .frontend import recruit_job_url

    base = request.url_root.rstrip('/') if has_request_context() else ''
    if not base:
        base = (Setting.get('site_url') or '').strip().rstrip('/')
    freq = Setting.get('seo_sitemap_changefreq_article') or 'monthly'
    prio = Setting.get('seo_sitemap_priority_article') or '0.6'
    urls = []
    for j in (RecruitJob.query.filter_by(is_enabled=True, is_deleted=False)
              .order_by(RecruitJob.updated_at.desc()).limit(2000)):

13. 开发与调试流程

  1. 在 plugins/ 下按第二章结构创建目录与文件（slug 即目录名）。
  2. 启动应用（开发模式 python run.py，debug 自动重载）——启动时全量导入所有插件，导入失败会在管理页标红并显示原因，不拖垮站点。
  3. 后台「插件管理」→ 启用：自动种子权限点、给预设角色补授权、db.create_all() 建表——全程幂等，可反复启停。
  4. 侧边栏出现插件菜单 → 开始 CRUD 迭代；前台验证 /jobs、详情、伪静态开关两种模式、禁用后 404。
  5. 改完代码重启生效（启停动作本身无需重启；插件代码变更需要重启进程重新导入）。
  6. 发布：把插件目录打包为 zip（含 manifest.json + __init__.py）→ 其他站点「插件管理 → 上传插件」直接可用；也可在本站「下载」按钮导出当前源码包。

14. 生命周期：上传 / 下载 / 卸载（builtin: false 的意义）

  • 上传：8 层校验（格式/完整性/路径穿越/符号链接/manifest/必备文件/根识别/目标检查），全程临时目录，失败不落盘。
  • 下载：一键打包 zip（单目录形态），含全部源码与模板，可在其他站点直接上传复用；写入导出审计。
  • 卸载：红色警告模态框 + 图形验证码二次确认后物理删除 plugins/recruit/；内置（builtin:true）或启用中禁止卸载；卸载后运行期注册表同步移除（菜单/导航/聚合立即消失），数据表与数据保留——重新上传同名插件包即恢复。
  • 发布到社区时建议 builtin: false（用户可自主卸载）；官方随核心分发的插件才标 true。

15. 自测清单（插件发布前必过）

  • 插件目录放入后，启动应用无异常；插件管理页显示"已加载"、版本/作者/说明与 manifest.json 一致，非内置插件显示卸载/下载按钮。
  • 启用：权限点种子成功、预设角色授权成功、插件表存在（recruit_jobs / recruit_applications）、侧边栏菜单按权限显示。
  • 后台 CRUD：创建/编辑/删除/批量 → 审计日志有记录、模块筛选下拉含「招聘管理」；非法输入（空标题/坏日期）被拒绝且有提示。
  • 前台路由：动态 200；伪静态开 /job-<id>.html 200、关 404；核心 /article-<id>.html、分页 /{slug}-{N}.html 不被劫持。
  • 表单与上传：验证码错误拒绝且一次性消费；截止前后台双重拒绝；docx/xlsx/pdf 成功入库落盘，exe 等非法类型拒绝；简历下载原始文件名正确。
  • 前台导航：启用后各主题导航出现插件入口；禁用后消失；与栏目导航并存不重复。
  • 模板函数：主题中调用 → 渲染；禁用插件 → 同一模板不报错、返回 fallback 空值。
  • API（如有）：api_enable=on 200 / off 404；Token 缺失 401；插件禁用后 404。
  • sitemap：/sitemap.xml 含插件 URL；禁用后消失。
  • 禁用/重启用：禁用 → 路由/菜单/导航/API/sitemap 全部隐身；重新启用 → 历史数据恢复，权限/建表不重复。
  • 卸载：验证码确认后目录删除、列表消失；数据表保留；重新上传同名包恢复。

16. 常见陷阱与最佳实践

  • 后台路由 endpoint 命名：admin.recruit_*。不要为后台自注册新蓝本，否则后台前缀切换时你的路由不会即时失效；前台才用独立蓝图。
  • 前台模板生成插件对象链接时用注册的 URL 全局函数（recruit_job_url(j)），不要写 {{ j.url }}——模型没有该属性时 Jinja 静默输出空 href。
  • 文件名判断上传类型时，用 secure_filename 之前的原始文件名取后缀（中文文件名经 secure_filename 处理后缀会丢；核心 save_upload_file 已处理，直接复用）。
  • 新建数据库时，模型 import 必须发生在 db.create_all() 之前——__init__.py 顶部显式 from . import admin（admin.py 再导入 models.py）。
  • __init__.py 末尾必须 plugin = RecruitPlugin()，否则核心判定插件加载失败。
  • 声明伪静态路由（如 /job-<id>.html）后，把它加入回归测试：确保核心 /article-<id>.html 与栏目分页 /{slug}-{N}.html 不被劫持。
  • 验证码校验后立即 session.pop（一次性消费，防重放）；前台交互页不要接页面缓存。
  • 模板中使用字典时写 g['items'] 而非 g.items——后者命中 dict 的 items() 方法。
  • 后台模板脚本块是 {% block js %}；子模板定义父模板不存在的块名会被静默丢弃（无报错）。
  • 业务规则（如截止时间判断）收口在模型方法，前后台共用，避免散落的时间比较。

十七、主题管理（v2.2）

入口：后台侧边栏「系统设置 → 主题管理」（权限点：system:settings）。v2.2 起前台主题的切换、上传、删除、下载统一在本页完成，「网站设置」中的原主题下拉框已移除并替换为引导卡片。

1. 主题列表

列出 themes/ 目录下全部主题的名称、版本、作者、说明、模板数与状态：

  • 使用中（绿色高亮）：当前启用主题，行内提示「已是当前使用中」。
  • 未启用：可一键启用。
  • 模板不完整（标红）：缺失必备模板，操作按钮灰显，悬停提示缺失明细与补齐指引。
  • 官方内置主题带「官方内置」徽标（manifest builtin:true，共 default/blue/manufacturing/service 四套）。

2. 上传主题

支持 .zip / .tar.gz / .tgz 压缩包，单目录形态（<slug>/manifest.json ...）或平铺形态（manifest 在包根）均可，自动归一化。上传需通过 8 步校验：

#校验项失败处理
1扩展名白名单（.zip/.tar.gz/.tgz）拒绝
2压缩包完整性（损坏包）拒绝
3路径穿越（预检 + _safe_join 双重拦截）拒绝

上传全程使用临时目录，任何校验失败不写入 themes/，finally 彻底清理临时文件；成功后写入上传审计（含 action/version/author/file_count/size_kb）。

3. 启用主题

启用前再次强检必备模板，缺失直接拒绝；通过后写入 Setting site_theme 并记录 OP_CONFIG_CHANGE 审计（含旧主题 → 新主题）。前台即时生效、无需重启；模板解析链保持「主题覆盖 → 插件自带 → default 兜底」。

4. 删除主题

  • 点击「删除」弹出红色警告模态框，需输入图形验证码确认（一次性消费防重放，独立于登录验证码）后才会物理删除 themes/<slug>/ 目录。
  • 官方内置主题不可删除（会导致系统模板缺失）；启用中的主题不可删除（须先切换到其他主题，含目录名与 manifest slug 双重判断）。
  • 删除动作写入 OP_DELETE 审计。

5. 打包下载主题

列表「下载」按钮把主题目录打包为 zip（单目录形态，与上传校验完全兼容），含 css/、js/、images/、fonts/ 全部静态资源，可在其他站点直接上传复用；下载写入导出审计（含版本/文件数/大小）。

6. 安全兜底

get_active_theme() 在当前启用主题目录不存在或模板不全时自动回退 default 主题，即使主题目录被误删，前台也不会白屏。

十八、国际化（v2.3）

v2.3 基于 Flask-Babel 实现界面文案的中英文自由切换，前台 + 后台全站生效。默认关闭（i18n_enable=0）：关闭时全站按默认中文渲染，与 v2.2.0 行为完全一致，不影响现有中文站点；仅界面文案（菜单、按钮、提示等静态字符串）参与翻译，栏目名/文章标题等内容数据不翻译。

1. 后台配置与语言切换

入口：后台侧边栏「系统设置 → 国际化」（权限点：system:settings），可视化配置三项并写入审计日志：

设置项默认值说明
国际化总开关 i18n_enable关闭关闭时不读取翻译文件，全站中文渲染
默认语种 i18n_default_localezh所有自动检测失败后的兜底语种
可用语种清单 i18n_available_localeszh逗号分隔，如 zh,en；决定语言切换器显示哪些语种

语言切换器：后台顶栏与前台主题 base.html 导航栏均会渲染语种下拉（全局函数 available_locales() / current_locale()）；未启用 i18n 或可用语种只有一个时自动隐藏。后台切换路由为 /admin/set-locale?lang=xx&next=...，写入会话后跳回原页面。

当前语种判定优先级（[app/i18n.py](app/i18n.py)）：

  1. URL 参数 ?lang=en（一次性生效并写回 session）；
  2. session 中记录的语种；
  3. cookie 中的语种；
  4. 浏览器 Accept-Language 头自动匹配可用语种；
  5. 默认语种 zh 兜底。

2. 模板标记与翻译工作流

核心模板中的可翻译字符串用 _() 标记：

<!-- 后台/主题模板 -->
<p>{{ _('仪表盘') }}</p>
<input placeholder="{{ _('搜索文章') }}">

翻译文件位于 app/translations/<语种>/LC_MESSAGES/messages.po（当前提供 en 英文）。.po 源文件入库，.mo 编译产物不入库（已在 .gitignore 排除），部署时需编译一次：

# 安装提取工具（Babel 已随 Flask-Babel 安装）
pip install Babel

# 1. 修改模板后重新提取字符串
pybabel extract -F babel.cfg -o app/translations/messages.pot app/

# 2. 更新各语种 .po（新增字符串追加、删除字符串标记过期）
pybabel update -i app/translations/messages.pot -d app/translations

# 3. 手工补全/校对 .po 中的 msgstr 后编译
pybabel compile -d app/translations

# 新增语种（如日语）示例
pybabel init -i app/translations/messages.pot -d app/translations -l ja
注意：① pybabel update 可能把相近字符串模糊匹配为旧翻译，编译前请检查 #, fuzzy 标记行并修正；② 中文（zh）为源语言，无需翻译文件。

★ 插件国际化实现方式（v2.3 新增独立翻译域）

每个插件拥有独立翻译域（domain 均为 messages，但各自存放于自己的 translations 目录），插件下载/上传打包时其译文随目录携带，与核心翻译互不干扰。

1. 目录结构与 get_i18n_dir() 钩子

在插件目录下新建标准 translations 目录（与核心同结构）即可启用独立翻译域，无需额外注册：

plugins/
  my_plugin/
    __init__.py            # 继承 PluginBase
    admin.py / frontend.py # Python 层视图/路由
    templates/
      my_plugin/
        index.html         # 后台/前台模板（用 {{ _p('my_plugin','原文') }}）
    translations/          # ★ 独立翻译域（核心启动时自动发现）
      messages.pot         # 本插件待翻译 msgid 模板（提取生成）
      en/LC_MESSAGES/
        messages.po        # 英文翻译源（入库）
        messages.mo        # 编译产物（不入库，部署时 pybabel compile -f）
      ja/LC_MESSAGES/      # 其他语种按需新增
        messages.po / .mo

核心 PluginBase 默认实现：get_i18n_dir() → 插件目录/translations；如需自定义（例如多插件共用同一翻译）可覆写该方法，返回绝对路径即可。启动时 plugin_system._register_instance() 会校验目录存在并调用 app.i18n.register_plugin_i18n(slug, 目录, domain='messages') 登记元数据。

2. 模板标记 {{ _p('<slug>', '原文') }}

v2.3 核心在 Jinja 全局注入了 _p(slug, msg)，所有插件模板必须使用显式 slug 版，禁止混用核心域的 _()（否则插件独立发布后译文缺失）：

<!-- plugins/my_plugin/templates/my_plugin/index.html -->
<h3>{{ _p('my_plugin', '我的插件列表') }}</h3>
<input placeholder="{{ _p('my_plugin', '请输入关键词') }}">
<form onsubmit="return confirm('{{ _p('my_plugin', '确认删除该项？') }}');">

包含变量的文案使用标准 Python 占位符（{0}、{name}），保持原样即可（.format() 插值）。

3. Python 层 plugin._('原文') / self.ngettext(s, p, n)

插件 Python 代码中使用 PluginBase 便捷方法（内部委托 app.i18n.plugin_gettext()，线程安全缓存）：

from app.plugin_api import PluginBase
from flask_babel import gettext as _gettext  # 仅当复用核心 msgid 时用

class MyPlugin(PluginBase):
    slug = 'my_plugin'

    @property
    def name(self):
        # ★ 插件菜单显示名：用 self._()，保证切换语言时翻译
        return self._('我的插件')

    @property
    def audit_modules(self):
        return [('my_plugin', self._('我的模块'))]

    def get_admin_menu(self):
        return [{
            'label': self._('菜单项A'),
            'endpoint': 'admin.my_plugin_index',
            'icon': 'fa-cube',
            'permission': 'my_plugin:manage',
            'active_prefix': 'my_plugin',
        }]

    def some_view(self):
        # flash 提示 / 异常消息：用 self._()（或需走核心通用文案时再 _gettext）
        flash(self._('保存成功'), 'success')
核心 vs 插件域选择：
  • UI 文案属于该插件独有 → 插件域：模板用 _p()，Python 用 self._()；
  • 复用核心已有的通用文案（如「确认删除」「保存成功」「非法请求」）→ 可用 from flask_babel import gettext as _gettext；
  • 最保险做法：所有插件页面/插件菜单一律先走插件域，通过 plugin_system.plugin_admin_menus() 再做核心域兜底。

4. 提取 / 更新 / 编译命令

由于 Babel 自带 Jinja 提取器仅识别 _ / gettext / ngettext，无法识别插件模板自定义的 _p(slug, msg)，因此需要「自定义扫描 + Babel Python 提取」合并生成 pot：

# ---- 推荐做法：在项目根运行，使用根目录自带的提取脚本（开源版参考）----
#
# 原理：
#   A. 正则扫描 templates/**.html：匹配 _p('', '') 取 msgid
#   B. pybabel 扫 /**.py：识别 self._(...) / gettext(...) / lazy_gettext(...)
#   C. 两者去重合并 → plugins//translations/messages.pot
#
# ---- 或手动执行以下 Babel 命令（仅 Python 层部分，模板 _p 需自己补写进 pot）----
#
# 1) 为插件单独写一份临时 babel.cfg（放在项目根），例如 _babel_plugin_my.cfg：
[python: plugins/my_plugin/**.py]
encoding = utf-8
[jinja2: plugins/my_plugin/templates/**.html]
encoding = utf-8

# 2) Python 层 + 模板 _p 合并生成 pot
pybabel extract -F _babel_plugin_my.cfg \
  -k _ -k gettext -k ngettext:1,2 -k lazy_gettext \
  -o plugins/my_plugin/translations/_babel_raw.pot plugins/my_plugin
# 然后用正则脚本把 _p(...) 扫出来的 msgid 追加到 messages.pot 并去重

# 3) 新增语种（首次）/ 更新已有语种（迭代）
pybabel init   -i plugins/my_plugin/translations/messages.pot \
  -d plugins/my_plugin/translations -l en
pybabel update -i plugins/my_plugin/translations/messages.pot \
  -d plugins/my_plugin/translations -l en --previous

# 4) 手工补全 plugins/my_plugin/translations/en/LC_MESSAGES/messages.po 中
#    的空 msgstr，然后编译（部署前必做）
pybabel compile -f -d plugins/my_plugin/translations -l en

# 5) 重复 1~4 步，为每种目标语种生成 messages.po / messages.mo

根目录 babel.cfg 仅扫 app/ 核心。5 个官方内置插件 + recruit 的提取脚本参考随仓库 _extract_plugin_i18n.py / _fill_tr.py 提供（运行后自行删除）。

5. 运行时懒加载与中文回退策略

  • 懒加载 + 线程安全缓存：_get_plugin_t(slug, locale) 首次访问才读取 .mo/.po，以 (locale, slug) 为键线程安全地写入 _t_cache（_PLUGIN_I18N_LOCK 防并发重建），后续请求直接复用。
  • zh 直接回退：当 current_locale() 以 zh 开头时，plugin_gettext() 立即返回 message 原文，不读翻译文件，兼容中文默认站点零性能损耗。
  • 插件未提供翻译目录：register_plugin_i18n() 未登记，调用 _p() 时 fallback 返回原文（不报错）。
  • .mo 未找到或损坏：fallback 到原文；开发环境下如果只写了 .po 未 compile，_load_plugin_translations() 会临时 shell 调用 pybabel compile 生成一次性 mo（正式部署前请务必显式 pybabel compile -f）。
  • locale 大小写/区域：en_US 先查 en_US/ 再退 en/；en 再退 en_* 目录。
部署提醒：由于 .gitignore 排除了所有 *.mo（方便开发），部署/打包 zip 上传插件前，必须对每个插件 translations 目录执行一次 pybabel compile -f -d plugins/<slug>/translations -l <lang>；否则站点后台英文下插件页仍然显示中文。
